안드로이드 앱 인수인계 — 웹 쪽에서 확인한 사항

작성 2026-11-19, 21:05 시험 결과와 웹 코드 지도 추가 (주피터 요청: 1주일 뒤 안드로이드 앱 구현 후 정리) · 이 문서는 문서만 추가한 것이며 android/ 코드, PR #1207, install.html은 건드리지 않았습니다.

1. 오늘의 결론

  • 같은 Wi-Fi에서는 두 기기가 연결되고, 서로 다른 이동통신망에서는 연결되지 않습니다. 호출·수락·대화 흐름 자체는 정상이며 막히는 곳은 통신망 사이의 경로입니다.
  • PWA(웹앱) 설치와 "알림을 누르면 앱으로 열리기"는 웹 코드로 해결하지 못했습니다. 안드로이드 앱이 필요한 이유가 여기에 있습니다.
  • 이동통신망 사이 연결은 앱이 크롬 엔진(Trusted Web Activity)을 쓰는 한 앱에서도 같은 조건이면 재현될 가능성이 높습니다. 앱이 설치와 알림 문제를 덜어도 이 문제는 따로 풀어야 합니다.

3. 안드로이드 앱이 맡아야 할 것 (요구사항)

  1. 알림을 누르면 항상 앱 화면으로 열기. 웹 푸시는 크롬이 PWA와 탭 중 어디로 열지 정하며, 주피터 폰에서 알림을 누르면 크롬 탭이 열렸습니다. 앱은 FCM을 직접 받으므로(NaviMessagingService, 채널 CH_CALLS) 호출 알림이 항상 앱의 화면(MainActivity)을 열게 해야 합니다. 웹에는 알림 탭 시 callTap=1로 열면 90초 동안 자동 수락하는 처리가 있습니다(p2p-chat.js).
  2. 호출·초대 알림이 화면이 꺼진 상태에서도 소리와 함께 도착해야 합니다. 높은 우선순위 채널, 전체 화면 알림(full-screen intent) 검토를 권합니다.
  3. 배터리 최적화 제외는 앱이 MainActivity에서 직접 요청합니다. 웹의 "배터리 보호를 해제…" 팝업은 앱 안에서는 뜨지 않아야 합니다.
    확인 필요: 웹은 앱 안 여부를 /; wv\)|NaviApp/ 또는 window.NaviAndroid로 판별합니다(notify-gate.js의 _inNativeApp). 현재 앱은 androidbrowserhelper(Trusted Web Activity)를 쓰므로 UA에 ; wv)가 없어 앱 안에서도 웹 배터리 팝업이 뜰 수 있습니다. 앱은 시작 주소에 ?app=1 같은 표식을 붙이거나, 첫 로드의 document.referrer가 android-app://kr.naviweb.app인지 웹이 확인하도록 맞춰야 합니다.
  4. 설치 게이트(src/pwa/install-gate.js)는 standalone 표시 모드에서는 뜨지 않습니다. TWA는 standalone으로 보이므로 앱에서는 게이트가 필요 없지만, 앱 안에서 게이트·팝업이 뜨지 않는지 실기기로 확인해야 합니다.
  5. 가입 직후 자동 로그인. 가입을 마치면 인증번호(OTP) 창 없이 바로 로그인되어야 합니다(주피터 요구). 웹에서는 아직 근본 원인을 확정하지 못했고, 앱에서도 같은 요구가 유지됩니다.
  6. 주소는 naviweb.kr 기준. hondi.net 주소는 폐기되었습니다. 앱의 시작 주소, Digital Asset Links, 앱 안의 주소 참조에 hondi.net이 남아 있는지 점검해야 합니다.

4. 이동통신망 간 연결 (WebRTC) — 확인된 사실

  • 도동(KT LTE)과 주피터(3G급, rtt 400~550ms)가 서로 다른 통신망일 때 두 기기 모두 호스트·srflx·relay 후보를 갖고도 연결 후보 쌍 65~74개가 응답 없이 시간이 지나 약 33~43초에 failed로 끝났습니다.
  • 중계 서버(Cloudflare TURN)는 정상 응답합니다. /turn/credential은 turn:3478, turns:5349, turn:443, turn:80과 자격증명을 내려줍니다.
  • TCP/TLS 중계(transport=tcp, 80/443/3478/5349) 후보 수집은 모두 Address not associated with the desired network interface(701)로 실패하고, UDP 중계와 STUN 일부는 시간 초과(TURN allocate request timed out)였습니다. 한 이동통신망에서 UDP가 막혀 있고 TCP/TLS 중계도 크롬이 만들지 못하는 상태일 가능성이 있으나 확정하지 못했습니다.
  • 수락 후 주피터 폰의 후보 추가(addIceCandidate)가 전부 실패했으나, 오류 문구가 50자에서 잘려 있었습니다(#1235로 전문 기록하도록 수정, 새 코드 기록은 아직 없음).
  • 앱이 TWA인 한 같은 크롬 엔진이므로 같은 현상이 재현될 가능성이 높습니다. 대안은 앱에 네이티브 WebRTC를 두는 방법(큰 작업)과 중계 설정(TCP/TLS 우선, relay 강제 등)을 바꾸는 방법입니다.

5. 미해결 항목

항목상태·메모
가입 후 hondi.net/webapp.html로 이동하고 OTP 창이 뜸코드에서 이동 지점을 찾지 못함(프록시 Worker, /webapp.html 이동도 naviweb.kr 안에서 끝남). 주소창 직접 입력에서도 발생했다고 보고됨. 옛 서비스워커·옛 PWA 아이콘 가설은 확인 못함.
PWA 설치 불가크롬이 "이 앱을 설치할 수 없습니다"(바로가기만 가능)라고 답함. 매니페스트·아이콘·서비스워커는 정상(200). Google Play 서비스/계정, 삼성 자동 차단, 크롬 버전이 의심되나 미확인.
알림을 누르면 크롬 탭이 열림서비스워커는 openWindow를 요청함. PWA가 옛 hondi.net 기준으로 설치되어 범위가 어긋났는지 확인 요청했으나 답 없음. 도동 폰은 PWA 미설치.
대화창이 "새 탭"이 아니라 "새 창"으로 열린다는 지적코드는 window.open(url,'_blank')(새 탭). 원하는 동작이 "같은 화면 안에서 대화 상대 탭 전환"인지 결정 필요(구조 변경).
수락한 쪽(주피터)에 상대와의 대화창 탭이 열리지 않음현재는 받는 쪽이 새 탭을 열지 않고 메인 화면이 대화창으로 전환됨. 구조 결정 필요.
메인 화면 왼쪽 위 나비 로고가 깨져 보임PC에서는 같은 이미지가 정상. 폰 캐시 의심. 폰 사이트 데이터 삭제 뒤 재확인 필요.

6. 앱 설치 후 첫 시험 (2026-11-19 21:05)

  • 조건: 주피터와 김동(구 "도동") 두 폰에 모두 안드로이드 앱을 설치했고, 김동 폰에는 PWA도 있습니다. 주피터가 김동을 대화에 초대했습니다.
  • 결과 1: 초대 알림이 김동에게 도착했고, 누르자 앱이 아니라 PWA가 열렸습니다. 알림의 출처(앱의 FCM인지 웹 푸시인지)는 확인하지 못했습니다.
  • 결과 2: 김동의 PWA가 주피터의 앱에 연결을 시도했으나 실패했습니다. 두 폰이 같은 Wi-Fi였는지는 기록이 없고, 진단도 받지 않았습니다(사용자 판단: 불필요).
  • 해석
    • 앱과 PWA가 함께 설치된 사용자에게 서버가 웹 푸시와 FCM을 둘 다 보내면, 웹 푸시는 서비스워커가 띄우므로 눌렀을 때 PWA·크롬이 열립니다. 앱 설치 사용자에게는 FCM만 보내고 웹 푸시는 끄는 구조가 필요합니다(앱이 FCM 토큰을 서버에 등록, 서버가 사용자별로 경로 선택). 알림 상단 이름이 "나비"인지 "Chrome"인지로 출처를 구분할 수 있습니다.
    • 앱 알림인데도 PWA가 열렸다면 앱의 알림 탭 처리(MainActivity 인텐트)가 PWA로 이어지는 것이므로 앱 쪽 수정 대상입니다.
    • 연결 실패는 다른 통신망이었다면 4절의 알려진 현상과 같습니다. 앱이 TWA(크롬 엔진)인 한 앱 설치만으로 풀리지 않는다는 것이 이번 시험의 의미입니다. 같은 Wi-Fi 대조 시험은 아직 하지 않았습니다.

7. 웹 코드 지도 — 앱 구현 때 참고 (이번 세션에서 파악한 구조)

주제위치·사실
주소 구조naviweb.kr은 Cloudflare Worker 프록시(mail 저장소 ops/naviweb-proxy/worker.js)입니다. 폰의 /는 app.naviweb.kr/webapp.html 내용, mail.naviweb.kr은 메일 앱을 가리킵니다. Location 헤더는 이 두 출처만 되돌려 씁니다. 진단 경로 /__whoami. hondi 저장소의 CNAME은 hondi.net(GitHub Pages)입니다.
출처별 저장소계정(localStorage)은 출처별이라 hondi.net으로 열리면 naviweb.kr 계정이 없어 OTP 로그인 팝업(_startSmsLogin)이 뜹니다. 앱의 시작 주소가 naviweb.kr 하나로 고정되어야 하는 이유입니다.
배포·캐시 지연main 병합 뒤 Pages 배포 약 1~2분, 파일 Cache-Control: max-age=300, Worker 엣지 TTL 약 2분, 서비스워커 캐시가 추가로 지연시킵니다. 시험은 병합 5분 뒤 앱을 완전히 종료하고 다시 열어 시작해야 합니다. 진단 rev로 새 코드 여부를 확인합니다.
설치 게이트src/pwa/install-gate.js: 폰 브라우저 탭에서 로그인 후 PWA 설치를 요구. standalone이면 건너뜀, ?dev=1 건너뜀, "이번만 브라우저로 계속" 버튼(세션 저장소 navi_gate_skip). 스크립트 태그 버전 ?v=20261119c.
PWAsrc/pwa/gopang-pwa.js(installPWAWithPermission, beforeinstallprompt, 서비스워커 교체 시 자동 새로고침 _tryReload, 통화 중·최근 통화 3분 보호). 매니페스트: id·start_url /webapp.html?pwa=1, scope /. share_target이 가리키는 /share-receive.html은 naviweb.kr에서 404입니다.
알림src/pwa/sw.js의 notificationclick(clients.openWindow, callTap=1이면 90초 자동 수락). 알림·배터리 팝업은 src/gopang/ui/notify-gate.js(5초마다 점검, 건너뛰기 세션 10분).
P2P 통화src/gopang/ui/p2p-chat.js(발신 startP2PCall, 수락 흐름, 신호 처리 _handleSignalRow, 폴링 _startPoll, ICE 진단 _diagIce), 신호 전송 src/gopang/p2p/signal-auth.js(쿠키·지갑 인증, 인증 준비 최대 약 3초 대기), 중계 설정은 src/gopang/core/state.js의 fetchRtcConfig가 https://hondi-proxy.tensor-city.workers.dev/turn/credential에서 받음.
진단src/gopang/core/diag.js(DIAG_REV 현재 20261119-3), 판정 diag-verdict.js. 채팅창에 진단을 입력하면 보고서가 클립보드에 복사됩니다. 연결 요약에 후보 쌍 유형·검사 요청/응답 수가 들어 있습니다.
앱 현재 구성androidbrowserhelper(TWA) + Firebase Messaging(NaviMessagingService, 채널 CH_CALLS 등), MainActivity가 배터리 최적화 제외 요청. 패키지 kr.naviweb.app.
호출 중 새로고침 사고서비스워커 교체(controllerchange)가 자동 새로고침을 일으켜 수락 8초 뒤 연결이 끊긴 사례가 있었습니다. 앱 웹뷰·TWA에서도 통화 중 새로고침이나 화면 재생성이 없도록 주의해야 합니다.
도구 제약작업 셸에서는 naviweb.kr에 접속되지 않아(프록시 403) 실제 확인은 크롬 탭으로 했습니다. 폰에서 /__whoami가 Windows UA로 보였던 것은 "데스크톱 사이트" 모드 의심.
