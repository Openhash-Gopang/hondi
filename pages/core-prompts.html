핵심 프롬프트

call-ai.js·manifest-loader.js·worker.js를 직접 훑어, 어떤 SP가 실제로 얼마나 자주·무조건적으로 로드되는지를 근거로 정리했습니다. "중요해 보이는 것"이 아니라 코드가 실제로 그렇게 짜여 있는 것들입니다.

0단계 서버가 예외 없이 강제 주입 (worker.js)

클라이언트가 무슨 system 프롬프트를 보내든, 서버 쪽 _fetchUniversalLayers()가 요청 앞에 강제로 덧붙입니다. handleAIChat 경로는 화이트리스트 없이 100% 적용되고, handleLLMRelay/handleKlawRelay는 service_id가 UNIVERSAL_FORCED_K_SERVICES(K-119·K-경찰·K-헬스·K-서치 등 20개 서비스) 목록에 있을 때 적용됩니다.

UNIVERSAL-INTEGRITY (U0) 서버 강제 주입
용도: 모든 SP가 지켜야 할 최우선 원칙 — 안내만 하고 끝내지 않기
"안내로 끝내지 않는다"는 나비의 제1공리. 세 강제 문서 중 하나.
TASK-DELEGATION-GUIDE 서버 강제 주입
용도: 정보 제공이 아니라 실제 업무 대행을 하도록 강제하는 지침
"나비의 본래 용도는 업무 대행이지 문의 응답이 아니다"를 명시.
CONTROL-TOWER-PRINCIPLE 서버 강제 주입
용도: 여러 SP가 이어지는 오케스트레이션을 하나의 지휘 체계로 통제
K-Intent→Compose→Execute→Deliver→Report 오케스트레이션 체인이 "정보 나열"로 새지 않게 잡는 관제탑 원칙. 2026-08-06 신설 당시엔 이 체인에 전혀 안 걸려 있던 게 실제 버그(응답이 문서형으로 새는 원인)로 확인돼 강제 상속 대상에 추가됨.
worker.js:18204 — "CONTROL-TOWER-PRINCIPLE — 모든 SP 제1원칙"
1단계 유일 정본 오케스트레이터 (대체물 없음)

코드 주석에 직접 "대체물은 존재하지 않는다"고 못박혀 있거나, 사실상 유일한 진입점 역할을 하는 SP입니다.

AC-PRO-CORE 유일 정본
용도: 사용자와 대화하는 개인 AI 비서(AC)의 인격·판단 기준 본체
개인 AI 비서(AC) 본체. call-ai.js의 _loadAgentCommonSP()가 세션당 1회 로드해 캐시하고, 실패 시 폴백 없이 명확한 오류로 중단하도록 설계돼 있습니다(과거에 있던 742자짜리 축약 폴백은 안전장치가 없어 완전히 제거됨).
call-ai.js:98 — "AC-PRO-CORE는 유일한 정본이며, 그 대체물은 존재하지 않는다."
hondi_visitor_sp 기본 진입점
용도: 로그인·페르소나 결정 전, 첫 방문자를 맞는 기본 인격
아직 페르소나가 정해지기 전, desktop.html "물어보세요" 위젯이 로드하는 방문자 기본 인격. worker.js 조사에서 이 경로(_loadVisitorSP)가 한동안 관제탑 원칙을 한 번도 못 받고 있었다는 게 발견되어 2026-08-09에 강제 주입 대상으로 편입됨.
AC-FLASH-EXECUTOR 위임 시에만
용도: 가벼운 작업을 빠른 모델(Flash)에 위임할 때 쓰는 실행 지침
가벼운 실행을 hondi-flash 모델에 위임할 때만 로드되는 실행보조 SP. AC-PRO-CORE의 하위 실행기 역할.
2단계 업무 실행 파이프라인 (모델이 태그를 낼 때 조건부 호출)

AC-PRO-CORE가 실제 업무 처리가 필요하다고 판단하면 [CALL_KINTENT] 같은 태그를 출력하고, call-ai.js의 _parseAgentTags()가 이를 감지해 _forwardSwitchSP()로 아래 SP들에 순서대로 넘깁니다. 매 턴 무조건 도는 건 아니지만, "업무 대행"이라는 나비의 핵심 가치가 실제로 구현되는 자리입니다.

K-Intent (SP-19) [CALL_KINTENT] 태그
용도: 사용자의 말에서 어떤 서비스가 필요한지 의도를 분석
사용자 의도를 분석해 어떤 서비스로 라우팅할지 결정하는 파이프라인의 입구.
call-ai.js:1422 — _forwardSwitchSP(_loadKIntentSP, 'K-Intent')
K-Search (SP-18) 전담 검색 에이전트
용도: 나비 전체에서 실제 웹·정보 검색을 수행하는 유일한 창구
gwp-registry.js에 "나비 생태계 전체의 유일한 검색 실행 에이전트"로 명시. 다른 SP가 위임하는 검색까지 전부 이곳으로 모입니다.
K-Compose (SP-20) → K-Execute (SP-22) → K-Deliver (SP-21) → K-Report (SP-23) 순차 오케스트레이션
용도: 의도 파악 이후 응답을 조합→실행→전달→보고하는 4단계 실행 라인
의도 파악 다음 단계로 응답을 조합·실행·전달·보고하는 4단계. 이 체인에 CONTROL-TOWER-PRINCIPLE이 안 걸렸을 때 "한 번에 하나씩 지시" 대신 정보 나열로 새는 버그가 실제로 있었습니다.
K-Bank · K-Telecom · K-Estate (switch형) GWP 전환 태그
용도: 금융·통신·부동산처럼 별도 저장소 없이 현재 세션을 해당 도메인 SP로 전환
별도 저장소 없이, 현재 세션의 system을 그대로 바꿔치기(switch)하는 방식으로 전환되는 도메인 SP. SWITCH_SP_LOADERS 테이블에 등록돼 있습니다.
참고로 확인된 예외(죽은 경로) — profile-assistant SP를 오케스트레이션 중 자동으로 불러오던 _switchToProfileAssistantSP()와 [CALL_PROFILE_ASSISTANT] 태그는 코드 주석상 "2026-07-27부터 현재 미사용"이며, 지금은 방어적으로 무력화만 하고 있습니다. profile-assistant는 이제 설정 패널이 직접 호출하는 경로로만 쓰입니다 — 한때 핵심 경로였다가 빠진 사례라 참고용으로 남겨둡니다.
