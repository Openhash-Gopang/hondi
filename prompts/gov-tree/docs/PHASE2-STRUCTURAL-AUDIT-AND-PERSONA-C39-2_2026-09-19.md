# Phase 2 구조 감사 + 페르소나 C39-2 롤아웃 감사 — 2026-09-19

## 0. 방법론에 대한 정직한 고지 (먼저 읽을 것)

원 계획은 "330여개 SP × 10개 시나리오를 작성해 실제로 평가"였다. 실행 중
확인해보니 342개 SP(정정된 인벤토리, §1 참조) × 10건 = 3,420건을 대화
하나하나 시뮬레이션하는 것은 이번 세션 범위에서 불가능했다 — 대신
**전체 SP 파일에 대한 구조적 정합성 스캔**(존재 여부, 필수 섹션 유무,
확정 상태)으로 대체했다. 이는 ALL-SP-SCENARIO-EXPERIMENT-REPORT가 쓴
방법론과 같은 계열이며, 그 리포트가 자인했던 함정("파일 자체에 키워드가
있는지만 보고 상속 원칙을 놓친다")을 피하려고 이번엔 상속 구조(공통 SP
4개 문서, 오늘 재확인된 실제 라이브 체인)를 먼저 확정한 뒤 스캔했다.
**개별 SP가 실제 대화에서 시나리오에 어떻게 응답할지까지는 검증하지
못했다** — 이건 별도의(훨씬 큰) 실사 세션이 필요하다.

## 1. SP 인벤토리 재확인 — 330 → 342

지난 세션에서 도청 8개 SP를 페이지에 반영한 뒤 다시 집계하니 총
개별 SP(파일·템플릿) 수는 **342개**(도청 국/과 71→구 13+신 12단일창구,
그 외는 이전과 동일)다.

## 2. 전체 342개 구조 스캔 결과

| 상태 | 개수 |
|---|---|
| PASS | 231 |
| PARTIAL(경미한 결함) | 109 |

### 2-1. FAIL — 깨진 링크 (조치 완료)
`SP-ORGDIV-JILES-LIFELONG`(제주평생교육장학진흥원 평생교육팀)이 페이지에
`confirmed: true`로 등록돼 있었으나 실제 파일이 저장소에 없었다 —
`SP-ORGDIV-JILES-EDU`(같은 한글명, 실제 파일 존재)의 중복/구버전 잔재로
보인다. **페이지에서 이 중복 항목 제거**(EDU만 유지).

### 2-2. PARTIAL 109건 — 대부분 같은 패턴 하나
**과·팀 단위 SP 중 다수(주로 직속기관·출자출연기관·도청 일부 과)가
§2(완결 처리 업무)만 있고 §3(접수·안내만 하는 업무/타 기관 연계)이
없다.** 즉 "우리가 못 하는 일은 어디로 넘겨야 하는가"를 명시한 SP와,
명시하지 않은 SP가 저장소 안에 섞여 있다 — 후자는 실제 대화에서 자기
권한 밖의 일도 스스로 처리하려 들 위험이 있다(오늘 정비한 kgov
§처리 파이프라인의 STEP B "처분권 소재" 판단과 직결되는 결함).
이건 개별 SP 100여 개를 하나씩 고치는 문제라 이번 세션에서 손대지
않고 **다음 배치 작업 후보**로 남긴다.

예외 2가지(다듬을 필요 없음, 확인만):
- `SP-CITYDIV-*-CONSTRUCTION-*` 6개(서귀포 안전도시건설국 계열): §CAPABILITIES
  표 대신 §1-0/§1-1/§2/§3 구조를 쓴다 — AGENCY-AC-COMMON 공리 2(접수 이후
  심사·보완) 파일럿 구현이라 의도된 다른 구조. 결함 아님.
- `SP-ORGDIV-JTO-PLANNING`(제주관광공사 경영기획본부): 내용이 짧고 §3에서
  "세부 본부·부서명은 확인하지 못했다"고 스스로 정직하게 고지하고 있다 —
  완성도가 낮을 뿐 결함으로 볼 것은 아니다.

## 3. 페르소나(SP_common_guardrails 하위) C39-2 롤아웃 감사

**747개**라는 숫자 자체가 이미 문제였다 — 실제로는 이 폴더(`prompts/`
최상위)에 **구버전이 archive 안 되고 계속 쌓여있는 것**이 대부분이다
(예: `SP_architect`가 v2.8/v2.9/v3.0/v3.1/v3.3 5버전 전부 생존). 이건
`SP_common_guardrails`·`UNIVERSAL-common`에서 이미 발견했던 "스트래글러"
문제가 훨씬 큰 규모로 반복된 것이다 — **약 70개 페르소나 × 평균 4~5개
구버전 = 300개 안팎의 죽은 파일이 최상위 폴더에 쌓여있는 것으로 추정**
(정확한 수는 `sp-catalog.json`과 실제 파일 목록을 전수 대조해야 확정
가능 — 이번 세션에서는 안 함, 별도 대규모 정리 작업 후보로 남긴다).

`sp-catalog-categories.json`의 카테고리 `parent` 필드로 "전문화 없는
최상위 페르소나"만 정확히 골라 매니페스트가 가리키는 **최신 버전 파일**만
확인한 결과:

| 결과 | 개수 |
|---|---|
| 최상위 페르소나 카테고리 | 53개 (63개라는 예전 기록과 차이 — 카테고리 재편 때문으로 추정, 재확인 필요) |
| C39-2 있음 | 51개 |
| C39-2 없음 | **`SP_advisor`, `SP_nurse`** 2개 |

v3.27에서 "60개 미반영"이라고 했던 것이 지금은 2개만 남았다 — 롤아웃은
거의 완료된 상태다. `SP_advisor_v1_3.md`·`SP_nurse_v3_7.md` 이 둘만
C39-2([L2·L3 예외] 표준 템플릿)를 추가하면 이 감사 항목은 완전히
닫힌다(이번 세션에서는 반영하지 않음 — 개별 페르소나 SP 수정은 범위
밖으로 판단).
