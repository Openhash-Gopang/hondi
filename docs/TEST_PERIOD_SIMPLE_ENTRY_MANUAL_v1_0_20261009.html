테스트 기간 간편 입장과 GDC 무료 모드 — 켜는 법, 끄는 법, 끝난 뒤 되돌리는 법

테스트 기간 동안 사용자는 접속만 하면 쉬운 한국어 단어 아이디(예: 푸른바다)를 자동으로 받고, 전화 인증 없이 폰과 PC 어디서든 혼디의 모든 서비스를 GDC 충전 없이 제한 없이 이용한다. 두 기능은 모두 Cloudflare 스위치 하나로 켜고 끄며, 꺼져 있으면 코드는 원래 동작과 같다. 이 문서는 구조와 한계, 그리고 테스트가 끝난 뒤 정상 상태로 복구하는 절차를 기록한다.

작성일 2026-10-09 대상 hondi-proxy Worker · 웹앱 · KAuth PR #537 · #538 · #539

현재 상태와 비상 정지

스위치(Worker Secret)역할2026-10-09 상태
SIMPLE_AUTH_TEST아이디 자동 발급·전화 인증 없는 입장·고시 배너ON (값 1)
GDC_FREE_TESTGDC 차감·잔액 확인·무료 한도 소진 중단ON (값 1)

테스트 종료 예정일: 미정 — 결정되면 이 줄에 기재하고, 종료 후 실제 복구일도 함께 적는다.

비상 정지 — 문제가 생기면 즉시 이 두 줄. 몇 초 안에 반영된다. 
npx wrangler secret delete SIMPLE_AUTH_TEST --name hondi-proxy
npx wrangler secret delete GDC_FREE_TEST --name hondi-proxy
삭제하면 이미 발급된 테스트 토큰도 서버가 즉시 거부하고, 화면은 원래 로그인 흐름으로 돌아간다. 데이터는 지워지지 않는다.
원래 원칙과의 관계. 혼디의 원래 설계는 "PC는 인증 기기가 아니며, 폰에서 전화번호로 본인 인증한 사용자만 등록되고, PC에서 로그인하려면 자기 폰에서 확인 버튼을 누른다"이다(2026-09-18 사고 기록 §7). 테스트 모드는 이 원칙과 문자 인증을 테스트 기간 동안 잠정 중단하는 것이며(주피터 지시, 2026-10-09), 종료하면 원칙이 그대로 복원된다. 이번 변경은 메인 채팅의 인증 경로(MANDATORY_AUTH_PATHS, 지갑 세션)를 바꾸지 않았다. 2026-09-18에 KAuth를 메인 채팅에 이식했다가 기존 지갑 세션과 충돌해 전면 롤백한 전례가 있어, 이번에는 새 인증 오버레이를 띄우지 않고 기존 토큰 형식에 얹는 방식을 택했다.

사용자에게 보이는 동작

  • 첫 접속: 팝업 없이 아이디가 자동 발급되어 로그인된다. 아이디는 "형용사 + 명사"(예: 푸른바다, 향긋한해녀)이고, 이미 있으면 다른 조합을 먼저 시도한 뒤 마지막에만 숫자 두 자리를 붙인다.
  • 고시 배너(기기당 단 1회, 10초): 처음 접속한 기기에서만 화면 상단에 "테스트 기간 중 보안 모듈 잠정 중단 · GDC 충전 없이 무제한 이용 · 실제 개인정보는 입력하지 마세요"와 내 아이디가 10초 동안 표시되고 스스로 사라진다. 그 기기에서는 이후 어떤 페이지(hondi.net·klaw·plan·mail 등)에서도 다시 나타나지 않는다. 표시 시작 시각을 저장해 두므로, 그 사이 페이지가 새로고침돼도(서비스 워커 첫 설치 직후의 자동 새로고침 등) 남은 시간만큼 이어서 보인다. 배너에는 "다른 아이디로 입장", "다른 기기용 링크 복사", "기존 계정으로 로그인" 버튼이 있다.
  • 재접속: 같은 기기에서는 배너 없이 발급된 아이디로 자동 로그인된다. 서버 확인이 일시적으로 실패(타임아웃·502 등)해도 기억한 아이디는 지워지지 않는다. 복구 순서는 ① 공용 쿠키 hondi_pvt → ② 이 기기의 로그인 정보 gopang_user_v4 → ③ 기기에 백업한 hondi_test_id.
  • 모든 서비스 공유: 쿠키가 .hondi.net 전체에 걸리므로 hondi.net에서 받은 아이디가 klaw·plan·mail 등 KAuth를 쓰는 서비스에서도 그대로 인식된다.
  • 폰과 PC: 기기마다 처음 접속 때 각자 새 아이디를 받는다. 같은 계정으로 쓰려면 아래 주소 파라미터를 쓴다(배너는 10초 뒤 사라지므로). 같은 아이디면 같은 계정이다.
  • 기존(전화 인증) 사용자: 이미 전화 인증으로 로그인한 사용자는 자동 입장 대상이 아니며 로그인이 그대로 유지된다. 로그인이 없는 기존 사용자는 배너·입장 화면의 "기존 계정으로 로그인"으로 원래 로그인 화면에 돌아갈 수 있다.

안내가 사라진 뒤의 조작 — 주소 파라미터 ?testid=

배너가 없어도 아이디를 확인하거나 바꿀 수 있도록 주소 뒤에 붙이는 파라미터를 둔다. 주소창에는 남지 않으며(새로고침해도 반복되지 않음), 테스트 모드가 꺼져 있으면 무시된다. 폰에서도 hondi.net으로 열면 그대로 전달된다.

주소동작
https://hondi.net/?testid=푸른바다이 기기를 그 아이디로 전환한다(다른 기기에서 쓰던 아이디로 들어올 때). 배너의 "다른 기기용 링크 복사"가 이 주소를 만들어 준다.
https://hondi.net/?testid=show내 아이디를 확인하려고 안내를 10초간 다시 표시한다.
https://hondi.net/?testid=off이 기기의 테스트 아이디를 끄고 전화 인증 로그인으로 돌아간다(이후 자동 발급 안 함).

전화 인증으로 로그인한 실사용자의 로그인은 이 파라미터로 덮어쓰이지 않는다(off만 예외).

테스트 토큰 — 기존 phone_verify_token과 같은 형식

tid-<아이디>:<만료ms>.<HMAC-SHA256(PHONE_VERIFY_SECRET, "tid-<아이디>:<만료ms>")>

전화번호(e164) 자리에 tid-<아이디>가 들어간 것이 전부다. 실제 전화번호는 +로 시작하므로 충돌하지 않는다. 그래서 이 토큰을 받는 모든 곳 — K-서비스 공용 인증 게이트(_kAuth.resolveGuid), MANDATORY_AUTH_PATHS의 릴레이(klaw·kplan·kjit·kcity·gov), 토큰 갱신(/auth/refresh-token) — 이 별도 수정 없이 같은 계정으로 확정한다. 유효기간은 기존과 같은 30일이며 활동 중이면 슬라이딩 갱신된다.

계정 (PocketBase profiles)

  • handle = tid-<아이디>, nickname = <아이디>, is_public = false(공개 검색에 안 나옴), extra.test_account = true.
  • guid는 기존 가입과 같은 형식의 무작위 값(2601:db80:…)이다. 생성은 L1 기본 노드(l1-hanlim)에만 한다.
  • 프로필 생성 직후 훅(pb_hooks/main.pb.js의 K-Mail 기본 주소 배정)이 동작하면 kmail_user_settings 레코드가 함께 생긴다. 정리할 때 같이 지워야 한다.

켜기·끄기·확인

켜기

cd C:\Users\주피터\Downloads\hondi
npx wrangler secret put SIMPLE_AUTH_TEST --name hondi-proxy    # 값 입력창에 1
npx wrangler secret put GDC_FREE_TEST    --name hondi-proxy    # 값 입력창에 1

대시보드로 하려면 Cloudflare → Workers & Pages → hondi-proxy → Settings → Variables and Secrets → Add에서 Type을 Secret으로 하고 이름과 값 1을 넣은 뒤 Deploy한다.

반드시 지킬 것 3가지
  1. Secret 타입으로 넣는다. 이 저장소는 worker 관련 파일이 main에 머지될 때마다 GitHub Actions(deploy-worker.yml)가 자동 배포하는데, 이 워크플로는 --keep-vars를 쓰지 않는다. 대시보드의 일반 텍스트 변수는 다음 자동 배포 때 지워질 수 있다(Wrangler의 기본 동작으로 알고 있으며 직접 확인하지는 않았다). Secret은 배포해도 유지된다. 코드는 === '1'로 비교하므로 Secret이어도 똑같이 동작한다.
  2. --name hondi-proxy를 반드시 붙인다. 2026-10-09에 이름 없이 실행했더니 Wrangler가 wrangler.toml을 읽지 못하고 기본 이름 my-worker로 새 워커를 만들려고 했다. 그 질문에 y를 누르면 엉뚱한 워커에 Secret이 쌓인다. 같은 질문이 또 나오면 n으로 취소한다.
  3. 값 입력 때 별표(*)가 보이는지 확인한다. 같은 날 첫 시도에서 별표 없이 Enter를 눌렀더니 빈 값으로 "Success"가 떴고, 스위치가 켜지지 않았다. Wrangler는 빈 값도 성공으로 처리한다. 반드시 아래 확인 주소로 실제 상태를 본다.

그다음 시크릿 창에서 hondi.net에 처음 접속해 상단 배너와 아이디가 뜨는지 본다. 이전 스크립트가 캐시되어 있으면 Ctrl+Shift+R로 강력 새로고침한다.

테스트 종료 후 정상화(복구) 절차

순서대로 진행한다. 1~2단계(끄기)는 데이터를 지우지 않고 되돌릴 수 있다. 3단계(계정 삭제)부터는 되돌릴 수 없으므로 반드시 백업과 건수 확인 뒤에 진행한다.

종료 시점 확정과 사전 점검

  • 종료 시각을 정하고, 테스트 참가자에게 "종료 후에는 전화 인증 로그인으로 돌아가며 테스트 아이디는 삭제된다"고 알린다.
  • 테스트 중 사용량을 집계한다. Cloudflare Workers 요청 수와 DeepSeek 사용량(원가)을 기록한다. 사용량 로그(_recordAiUsage)는 계속 남아 있으므로 서비스별 원가 집계에 쓸 수 있다.
  • PocketBase 백업(스냅샷)을 만든다. 3단계에서 삭제가 일어나기 전에 반드시 필요하다.

스위치 끄기

npx wrangler secret delete SIMPLE_AUTH_TEST --name hondi-proxy
npx wrangler secret delete GDC_FREE_TEST    --name hondi-proxy

확인 주소를 다시 열어 {"ok":true,"enabled":false,"gdc_free":false}가 나오는지 본다. 끄면 다음이 자동으로 일어난다.

  • 이미 발급된 테스트 토큰을 서버가 모두 거부한다(TOKEN_INVALID, "테스트 기간이 종료되어 인증 토큰이 만료되었습니다").
  • 테스트 계정으로 로그인해 있던 브라우저는 다음 접속 때 테스트 로그인 정보와 공용 쿠키를 스스로 지우고 원래 로그인 화면으로 돌아간다.
  • KAuth는 남은 tid- 토큰을 지우고 전화 인증(device-link) 오버레이를 보여 준다.
  • 브라우저에 남는 hondi_tn(쿠키)·hondi_test_notice_until·hondi_test_id·hondi_test_optout 값은 스위치가 꺼진 뒤에는 아무 동작도 하지 않는 무해한 흔적이다. 다음 테스트 기간에 다시 켜면 이미 본 기기는 안내가 나오지 않는다(새 기간에 안내를 다시 보이려면 이 쿠키 값이 지워져야 한다).
  • GDC 과금·잔액 확인이 원래대로 동작한다. 무료 한도(평생 100원)는 테스트 중 소진되지 않았으므로 그대로 남아 있다.

Cloudflare에서 흔적 확인

대시보드 hondi-proxy → Settings → Variables and Secrets 목록에 SIMPLE_AUTH_TEST와 GDC_FREE_TEST가 없는지 확인한다. 실수로 my-worker가 만들어졌다면 Workers 목록에서 삭제한다.

테스트 계정 정리 (되돌릴 수 없음)

PocketBase 관리자 화면에서 진행한다. 테스트 계정은 worker.js의 L1_DEFAULT = 'https://l1-hanlim.hondi.net'가 가리키는 L1 기본 노드에만 만들어졌다.

엉뚱한 인스턴스를 지우지 말 것. 같은 서버(l1-hanlim-new)에는 이름이 비슷한 PocketBase 인스턴스가 40개 넘게 떠 있다(l1-aewol, l1-ara…, l2-jeju, l3-jejudo, l4-kr, l5-global 등). 삭제할 대상은 L1_DEFAULT와 정확히 같은 인스턴스(gopang-pb-hanlim.service, 접두사 없는 hanlim)여야 한다. 2026-09-18 조사에서 l3-jejudo 같은 이름이 비슷한 다른 DB를 한참 들여다본 실수가 있었다. 삭제 전에 화면의 접속 주소가 l1-hanlim.hondi.net인지 확인한다.
  1. profiles 컬렉션에서 필터 handle ~ 'tid-%'로 목록과 건수를 확인한다. %를 직접 쓰면 앞부분 일치로 동작한다. 실사용자 계정의 핸들은 전화번호 숫자이므로 이 필터에 섞이지 않아야 한다. 건수와 샘플을 눈으로 확인한 뒤 진행한다.
  2. 해당 guid 목록을 따로 저장해 둔다(연관 데이터 정리와 사후 감사용).
  3. guid로 연결된 연관 레코드를 먼저 지운다. 대표적으로 kmail_user_settings(owner_user_guid). 그 밖에 테스트 중 대화·세션·PDV·감사 로그 등이 어느 컬렉션에 쌓였는지는 컬렉션 목록에서 guid 필드로 확인한다.
  4. profiles의 tid- 레코드를 삭제한다.
서버에는 프로필 하드 삭제 방어 훅(pb_hooks/main.pb.js)이 있어, 잔액이 0이 아니거나 거래 이력이 있는 계정의 삭제 요청을 거부한다. 테스트 중 GDC 거래를 일으킨 계정은 삭제가 거부될 수 있다. 이 훅을 끄지 말고, 거부된 계정은 따로 목록을 만들어 원인(잔액·거래)을 확인한 뒤 판단한다.

코드 처리 결정

옵션 A — 코드는 그대로 둔다 (기본 권장). 스위치가 꺼져 있으면 코드는 원래 동작과 같다(시뮬레이션과 회귀 시나리오로 확인). 다음 테스트 기간에 Secret 두 개만 다시 넣으면 재사용할 수 있다. 정리할 것은 없다.

옵션 B — 코드를 완전히 제거한다. 머지된 세 PR을 최신순으로 되돌린다(모두 squash 머지이므로 일반 revert로 된다).

정상화 검증

  • /auth/test-mode → enabled:false, gdc_free:false
  • POST /auth/test-enter → 403 TEST_AUTH_OFF
  • 시크릿 창에서 hondi.net 접속 → 고시 배너 없음, 아이디 자동 발급 없음, 기존 로그인(전화 인증) 화면 표시
  • klaw·plan·mail 접속 → 전화 인증(device-link) 오버레이 표시
  • 전화 인증으로 만든 실계정 로그인이 정상이고, 로그인이 유지된다
  • 무료 한도를 소진한 테스트용 실계정으로 AI를 호출했을 때, 잔액이 없으면 402 "GDC 잔액 부족"이 나온다(과금이 다시 동작함)
  • 관리자 수동 차감(admin-correction)이 정상 차감된다
  • Cloudflare Secrets 목록에 두 항목이 없다

기록

이 문서 "현재 상태"의 종료일과 복구 완료일을 기재하고, 테스트 중 집계한 사용량·원가를 작업 이력에 남긴다. 테스트 중 발견한 문제는 아래 "작업 중 발견한 결함"에 이어서 적는다.

일부만 복구하려면. GDC 과금만 먼저 되돌리려면 GDC_FREE_TEST만 삭제한다(아이디 입장은 유지). 아이디 입장만 끄려면 SIMPLE_AUTH_TEST만 삭제한다(GDC 무료는 유지되어 모든 사용자의 차감이 계속 중단된다는 점에 주의).

알려진 한계

  • 전화번호가 필요한 기능(혼디 숫자 번호 등록 등)은 쓸 수 없다. 방금 한 문자 인증 토큰과 지갑 서명이 필요하다.
  • 지갑 서명 전용 경로는 막힐 수 있다. 테스트 계정은 프로필에 핀(pin)된 지갑 키가 없다. 전화 인증 토큰을 받는 경로는 모두 통과하지만, 서명만 받는 엔드포인트는 전수 확인하지 못했다.
  • 기기마다 새 아이디가 발급되고, 쿠키·저장소가 둘 다 사라지면(시크릿 모드·브라우저 데이터 삭제·iOS Safari 7일 제한·iOS 홈 화면 앱처럼 저장소가 분리된 경우) 새 아이디가 발급된다. 옛 아이디를 입력하면 복귀한다. 처음 받은 아이디는 DB에 남아 정리 대상이 된다.
  • 테스트 계정은 공개 검색에 나오지 않는다(is_public=false). 테스트 사용자끼리 서로 찾는 기능은 어렵다.
  • 메인 채팅(/chat/completions·/deepseek)은 2026-09-18 롤백 이후 MANDATORY_AUTH_PATHS에 없고, 요청 본문의 guid를 그대로 사용한다. 이번 변경이 만든 것이 아닌 기존 구조이며, 이번에도 바꾸지 않았다.
  • 스위치가 켜진 동안 모든 사용자의 GDC 차감이 중단되고, 로그인 없는 기존 사용자는 배너의 "기존 계정으로 로그인"을 눌러야 원래 로그인 화면이 나온다.
  • 정산 재시도 큐(아웃박스)에 테스트 전부터 대기 중이던 항목이 있었다면, 테스트 중 처리될 때 차감 없이 끝났을 수 있다(코드 흐름으로 추정, 미확인).

작업 중 발견한 결함

결함조치
실사용자 로그인 덮어쓰기 — 스위치 ON 상태에서 전화 인증으로 로그인한 사용자가 접속하면 공용 쿠키가 테스트 토큰으로 바뀌었다(KAuth와 웹앱 두 경로 모두, 시뮬레이션으로 재현). #538에 들어갔던 결함.#539에서 수정: 실사용자 토큰이 살아 있으면 자동 입장 건너뜀, "기존 계정으로 로그인" 탈출구 추가, 테스트 모드 확인에 4초 타임아웃.
웹앱이 먼저 아이디를 만들면 KAuth가 그 결과를 반영하지 못해 전화 인증 팝업이 뜰 수 있었다.공유 결과를 KAuth도 반영하도록 수정(#538).
쿠키가 사라지면 아이디를 잃어 새 아이디가 발급될 수 있었다.기기 저장소에 hondi_test_id 백업(#538).
두 사이트에서 서로 다른 아이디로 입장하면 방문 때마다 아이디가 번갈아 바뀔 수 있었다.공유 쿠키의 아이디를 우선하도록 수정(#538).
맥·iOS 입력기의 분해형 한글(NFD) 아이디가 거부될 수 있었다.서버와 화면에서 NFC로 정규화(#538).
안내가 0.1초만 보임(폰 시크릿탭 첫 접속, 2026-10-09 주피터 실사). 서비스 워커가 활성화 때 clients.claim()을 하고 PWA 코드의 controllerchange 핸들러가 첫 설치 여부를 가리지 않고 location.reload()를 하므로, 새 시크릿탭에서는 로드 직후 페이지가 한 번 새로고침된다. 이것이 유력한 원인이다(폰 기기에서 직접 확인하지는 못함). 또한 배너가 영구 표시 전제였던 것도 문제였다.안내를 "기기당 1회·10초"로 바꾸고 시작 시각을 저장해, 새로고침이 끼어도 남은 시간을 이어서 표시(시뮬레이션: 0.3초 뒤 새로고침 후 남은 ≈9.2초 표시). 서비스 워커의 첫 설치 새로고침 자체는 건드리지 않았다.
일시적인 서버 확인 실패가 "테스트 종료"로 오판됨 — /auth/test-mode가 502이거나 4초간 응답이 없으면 저장된 테스트 로그인과 쿠키를 지우고 새로고침했다(수정 전 코드로 재현). 재접속 때 "아이디를 기억"하는 요구와 정면으로 충돌.3상태(켜짐/꺼짐/모름)로 바꿔, 서버가 분명히 enabled:false라고 답할 때만 정리(수정 후 재현: 502·무응답 모두 아이디·쿠키 유지, 새로고침 없음).
머지 완료된 #537 위에 누적 패치를 적용하려다 충돌.머지된 PR과 내용이 같은지 먼저 확인하고, 최신 main 기준 차이분만 패치로 만든다(운영 규칙).

검증 방법

실제 worker.js를 모의 L1(가짜 DB) 위에서 돌리고, 클라이언트는 jsdom(가짜 브라우저)으로 폰과 PC를 각각 별개 브라우저로 흉내 냈다. 실제 브라우저·실제 PocketBase로는 확인하지 못했다.

  • PC 첫 접속 → 아이디 발급·배너·공용 쿠키, 재접속 자동 로그인, 같은 PC의 다른 서비스(KAuth)에서 같은 아이디, 서버 공용 게이트가 같은 계정으로 확정
  • 폰 첫 접속 → 다른 아이디 발급, PC 아이디 입력으로 같은 계정 전환, 폰 재접속 자동 로그인
  • 쿠키만 삭제된 경우 복구, 쿠키·저장소 모두 삭제된 경우 새 아이디, 웹앱과 KAuth 동시 로드 경합(계정 1개만 생성)
  • 스위치 OFF 후 정리·토큰 거부, 위조 토큰 거부, 토큰 갱신, GDC 잔액 조회
  • 실사용자 보호(KAuth·웹앱), "기존 계정으로 로그인" 탈출, 테스트 모드 응답 지연 시 4초 뒤 원래 화면
  • 안내 규칙: 첫 접속 10초 표시 → 0.3초 뒤 새로고침에도 남은 시간만 이어서 표시 → 11초 뒤 재접속은 배너 없이 같은 아이디 자동 로그인 → 다른 서비스(KAuth)에서도 안 보임, 실제 대기로 5초 시점 표시·10.4초 뒤 자동 소멸
  • 일시 장애(502·무응답)에서 아이디 유지, ?testid= 전환·show·off, 실사용자 로그인이 파라미터로도 덮어쓰이지 않음
  • GDC 무료 모드: 스위치 OFF에서는 게이트·차감이 L1을 호출하고, ON에서는 호출하지 않으며 관리자 차감만 호출한다

종료 후 실제 환경에서의 확인은 위 "정상화 검증" 체크리스트를 따른다.
