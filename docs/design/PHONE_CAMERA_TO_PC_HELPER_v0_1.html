폰 카메라 → PC 나비웹 도우미 증거 전달 설계 v0.1

2026-11-19 · 대상: 사용법 매뉴얼 제12장(마이크·카메라·파일 첨부) 갱신의 근거 설계 · 상태: 제안(미구현)

1. 목표와 시나리오

PC에서 나비웹 도우미가 민사소송 서류(소장·준비서면 등)를 작성하는 동안, 사용자가 폰 카메라로 종이 증거(계약서·영수증·내용증명·문자 화면)를 찍어 PC의 도우미에게 전달하고, 도우미가 그 내용을 근거로 서류를 다듬는다. 작성 흐름을 끊지 않고(PC 화면 유지), 원본 사진이 나비웹 서버에 평문으로 남지 않아야 한다.

2. 기존 자산 재사용 (새로 만들지 않는 것)

필요기존 구현비고
폰↔PC 동일 신원device-link(같은 개인키·guid), gopang-wallet.js동일 계정 로그인 상태면 별도 가입 없음
폰 깨우기웹푸시/FCM (_sendPushToGuid), 알림 탭 → URL호출 알림 수정(#1229)으로 도달성 개선됨
종단 암호화 전달/pdv/relay/push|pull (X25519 봉인, TTL 10분, 1회 소비)항목 최대 20건, 큰 사진은 압축·분할 필요
장기 보관 우편함case-mailbox(64KB 상한, 큰 파일은 R2+키 봉투)본 기능에는 과함 — 사용하지 않음
직접 연결WebRTC 데이터채널 + /signal/*, TURN1순위 경로로 시도, 실패 시 relay 폴백
사진 → AI 읽기채팅 위젯 image_url 첨부, 카메라 입력(capture=environment)OCR/비전 호출 경로 존재
증거 보관PDV(IndexedDB, 로컬 전용) + 해시만 서버case-core 해시체인 재사용 가능

     만료 30분, 사건 라벨(예: 소장 초안)

④ 복호 → PDV 저장(sha256) → "증거 후보" 목록에 표시

⑧ [촬영 종료] → 세션 s 폐기, 폰 임시 사진 삭제

4. 구성 요소와 계약

구성내용
세션capture:{guid}:{s} KV, TTL 30분. 값: pc_pub, 상태(open/closed), 수신 개수. 본문·사진 없음.
봉투{s, seq, sha256, sealed}. 서버 허용 필드 외 거부(case-mailbox 방식). 사진 1장 ≤ 1.5MB 목표, 초과 시 폰에서 재압축.
증거 레코드(PDV){id, case_ref, sha256, mime, taken_at, ocr_text, fields{type,date,amount,parties}, label, status: candidate|adopted|discarded}. 원본 바이트는 IndexedDB 블롭.
도우미 입력채택(adopted) 증거의 label + fields + ocr_text만 모델에 전달. 원본 이미지는 사용자가 "이미지로 직접 보기"를 선택할 때만.
인용 규칙초안의 사실 주장 문장은 증거 id 또는 "사용자 진술"로 출처 표기. 근거 없는 사실 주장은 새로 만들지 않음.

5. 안전·프라이버시 규칙

  • 평문 서버 비경유: 서버는 봉인된 암호문과 크기·시각만 본다. 세션 키는 PC 메모리에만 존재.
  • 사용자 확인 게이트: 후보→채택은 사용자가 명시. 미채택 증거는 모델에 보내지 않음.
  • 최소 전송: 모델에는 추출 텍스트·필드 우선. 이미지 직접 전송은 선택. 민감 항목(주민번호·계좌)은 PC에서 가림(마스킹) 도구 제공, 마스킹 후 해시를 별도 기록.
  • 수명: 세션 30분, relay 10분 1회 소비, 종료 시 폰 임시본 삭제, 증거 목록은 사용자가 삭제 가능.
  • 무결성: 원본 sha256을 PDV 해시체인에 기록하고 서버에는 해시만 보고(/pdv/report) → "촬영 시각에 존재했던 증거"의 사후 입증에 유리. 단, 이는 법적 증거능력을 보장하지 않음.
  • 법률 고지: 도우미는 서류 작성 도구이며 법률 자문이 아님. 제출 전 본인 확인을 화면·매뉴얼에 명시. 증거 번호(갑 제N호증)와 증거설명서 형식은 법원 양식에 맞춰 사용자가 최종 확인.
  • QR 폴백의 위험: QR에는 세션 id와 PC 공개키만 포함(개인키·계정 정보 없음). 타인이 QR을 찍어 사진을 보낼 수 있으므로 PC에서 수신 시 "새 사진 도착" 확인을 거치고 미확인 사진은 목록에 격리.

6. 단계별 구현안

단계범위성격
M0매뉴얼 제12장 갱신(이 설계 설명, "제공 준비 중" 표기)이번 PR
M1capture 세션 API + 폰 촬영 화면 + relay 전송 + PC 증거 목록(후보/채택)핵심
M2도우미 연동: OCR/필드 추출, 증거 인용 초안 다듬기, 불일치 경고, diff핵심
M3P2P 1순위 경로, 모서리 자동 보정, 마스킹 도구, 증거목록 내보내기개선

7. 미결정 사항 (사용자 결정 필요)

  1. 증거 이미지를 모델에 직접 보낼지(품질↑·노출↑) 추출 텍스트만 보낼지 기본값.
  2. QR 폴백(계정 비로그인 폰)을 M1에 포함할지.
  3. 증거 목록·인용 형식을 소송 외 서류(계약·민원)에도 공통 적용할지.
  4. 도우미 확장(별도 저장소)과 나비웹 페이지 사이 메시지 계약 — 확장 쪽 수정 범위.
매뉴얼 제12장의 "폰과 PC가 함께 일하는 방법" 절은 위 M1·M2가 구현될 때까지 "제공 준비 중"으로 표기한다. 구현 전에 사용 가능한 것처럼 안내하지 않기 위함이다.
