SESSION SUMMARY — 2026-09-06 세션 발견 정리

GDC 대출·신용평가, 실서버에서 처음으로 끝까지 돌았다 — 그 과정에서 만난 다섯 가지 문제

LEGAL-HOLD로 막혀 있던 GDC 대출(applyLoan)·신용평가· 상환(repayLoan) 기능을, "금융기관 종사자 필드테스터 한정"으로 범위를 재정의해 재개하고 실서버(L1, hanlim)에서 최초로 end-to-end 실행했다. register-key부터 상환까지 전 구간이 실제 조건으로 실행된 것은 이번이 처음이었고, 그 과정에서 스키마 부재·엔드포인트 부재·저장소 위치 오류·json 필드 설정 누락까지 서로 다른 다섯 가지 문제를 순서대로 만나 전부 해결했다. 이 문서는 향후 이어지는 테스트의 출발점으로 그 과정을 기록한다.

Overview
이 문서가 왜 있는가

GDC 대출·신용평가 기능은 이전까지 LEGAL-HOLD로 막혀 있어 실사용 조건에서 한 번도 실행돼 본 적이 없었다. 오늘 범위를 조건부로 재개하고 처음 끝까지 돌려보자, 다른 여러 세션에서도 반복돼 온 패턴 — "실사용 조건에 처음 도달해서야 드러나는 문제" — 이 그대로 재현됐다. 이 문서는 그 다섯 가지 문제와 해결 순서, 그리고 최종적으로 그린이 된 배포 절차를 기록해 다음 테스트 세션이 여기서부터 이어갈 수 있게 한다.

이 문서를 읽어야 하는 상황
GDC 대출·신용평가·상환 파이프라인을 이어서 테스트하거나 확장할 때 / validation_json_size_limit 류의 PocketBase 저장 오류를 마주쳤을 때 / LEGAL-HOLD가 걸린 기능을 필드테스트 목적으로 조건부 재개해야 할 때 / 마이그레이션이 어느 저장소에 있어야 자동배포가 되는지 헷갈릴 때.
Pipeline
전체 파이프라인 (그린 확인 완료)

다음 순서로 실서버(L1, hanlim)에서 전 구간 [PASS] 확인:

  1. register-key
  2. 프로필 TOFU 등록
  3. 관리자 로그인
  4. 재무제표 시나리오 등록
  5. applyLoan — 서명 검증 + 서버측 신용평가 계산 + 대출금 지급
  6. repayLoan — 실이체 + 원금/이자 분리

최종 성공 로그: gh run view 34063481327 --log

① · Scope
LEGAL-HOLD 2건(신용평가/대출) — 조건부 재개

대출과 신용평가 두 기능 모두 기존에 LEGAL-HOLD로 막혀 있었다. 전면 해제 대신, 범위를 "금융기관 종사자 필드테스터 한정"으로 조건부 재정의해 재개했다.

② · Schema
bs-* 재무제표 스키마 자체가 없었음

신용평가 계산에 필요한 재무제표(bs-*) 스키마가 아예 존재하지 않았다. 테스터 전용 목업 스키마를 신설해 해결했다.

③ · Endpoint
테스터 시나리오 등록 엔드포인트 자체가 없었음

테스트 시나리오(재무제표 등)를 등록할 수단 자체가 없었다. 관리자 전용 upsert 엔드포인트를 신설해 해결했다.

④ · Deploy Pipeline
마이그레이션이 gdc 저장소에 있었는데, gdc엔 자동배포 파이프라인이 없었음

해당 마이그레이션 파일이 gdc 저장소에 위치해 있었으나, gdc에는 push 시 자동배포하는 워크플로우가 없어 반영되지 않고 있었다. 마이그레이션을 hondi 저장소로 이관해 해결했다.

후속 필요
gdc 저장소 쪽 이력 동기화용 패치(09b)는 실제 동작엔 영향 없으므로(적용은 이미 hondi 쪽으로 완료됨) 급하지 않을 때 반영. 후속 과제 참고.
⑤ · PocketBase 0.22.x Trap
credit_snapshot json 필드 maxSize 누락
과거 account_risk_score.score_basis 버그와 동일한 원인 — 이 프로젝트에서 재발

최종 저장 단계에서 다음 오류로 막혔다: 

validation_json_size_limit — "The maximum allowed JSON size is 0 bytes."

PocketBase 0.22.x는 json 타입 필드에 options.maxSize를 명시하지 않으면 실서버에서 0바이트로 취급해 저장을 거부한다. gdc_test_loans.credit_snapshot 필드 생성 시 이 값을 빠뜨렸다. 과거 account_risk_score.score_basis 버그를 고쳤던 1788100001_fixed_account_risk_score_basis_maxsize.js를 템플릿 삼아 동일한 방식으로 수정했다. 

// getFieldById → maxSize = 2000000
// (기존 컨벤션과 동일하게 2,000,000 bytes로 설정)
일반화된 교훈
이 프로젝트에서 json 타입 필드를 새로 만들 때는 maxSize: 2000000을 컨벤션으로 항상 명시할 것 — 누락 시 로컬/스테이징에서는 통과하고 실서버에서만 저장 거부로 드러나는 경우가 있다.
