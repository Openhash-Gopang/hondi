# 세션 교훈 — "AI 메신저 테스트 버전"은 테스트가 아니라 프로덕션이었다
### 패널/메인 채팅 통합 격차 진단 + 오늘 발견·수정한 버그 7건 (2026-09-14)

> **참고**: 이 문서 작성과 거의 동시에 협업자 jejuro님이 같은 문제를
> 독립적으로 발견해 leaf 액션 태그 5종 이식 + 이름표 정정 + 별도 감사
> 문서(`SESSION_LESSONS_PANEL_VS_MAIN_CHAT_AUDIT_20260914_v1_0.md`, 메뉴
> 상단)를 먼저 병합했다. 이 문서는 그 작업과 겹치지 않는 나머지(AUTH
> 태그·K-Law 감시·OpenHash 앵커링·handleExpertTag 인자 누락)와, 그 이전에
> 있었던 나머지 6건의 버그(타임아웃·태그누락·진단도구·배너·캐시·GPS)까지
> 포함한 이날 전체 세션의 기록이다. 패널/메인 채팅 구조 자체에 대한 더
> 자세한 분석은 jejuro님의 문서를 함께 참고할 것.

## TL;DR

- `#ai-panel`(화면에 "AI 메신저 테스트 버전"이라는 태그라인이 붙어 있던 패널)은
  **2026-07-07부터 유일한 실제 기본 화면**이었다. `#message-list`(call-ai.js의
  `callAI()`가 기본으로 그리는 대상)는 그날 이후 `display:none`으로 숨겨진
  채 두 달 넘게 아무도 못 보는 화면으로 남아 있었다.
- 그런데 `#message-list`를 그리는 `callAI()`/`_callAIInner()`의 디스패치
  체인에는 정부 서류 처리, K-Search 실행, 재무제표 조회, 인증 단계 상향,
  K-Law 상시 감시, OpenHash 앵커링, **사용자 위치 컨텍스트**가 다 들어있었는데,
  이 중 상당수가 실제 기본 화면(패널)에는 애초에 이식된 적이 없었다.
- "AI 메신저 테스트 버전"이라는 이름표 자체가 이 격차를 두 달 넘게 가려왔다
  — 누구도 "테스트판이니 기능이 빠져 있겠거니" 하고 넘어갔다. 오늘 세션은
  이 이름표 때문에 몇 시간을 "진짜 메인 채팅은 따로 있다"는 잘못된 가정으로
  헤맸다.
- 오늘 이 격차를 메우고(패널에 6개 핸들러 이식), 이름표를 "최신 버전"으로
  고쳤다. 아래는 그 과정에서 발견·수정한 버그 7건과, 앞으로 같은 함정을
  피하기 위한 체크리스트다.

## 배경 — 재현 시도

주피터님이 실제 폰에서 반복 재현: "애월읍에서 가까운 행정복지센터를 찾아줘"
→ AI가 "찾아드릴게요. 바로 검색해볼게요."까지만 말하고 정지. 이 화면이
바로 위에서 말한 그 패널이었다.

## 발견 순서와 각각의 실제 원인

### 1. fetch 타임아웃 부재 (fetch 22곳) — 실제 원인 아니었음, 그래도 실버그였음

이전 세션이 CALL_GOVSYS/CALL_GOVTREE 두 곳에 45초 타임아웃을 걸어둔
것을 보고, 같은 클래스의 결함이 나머지 fetch 22곳에도 있을 거라 보고
전부 고쳤다(`AbortSignal.timeout(45000)`). **실제로 있던 결함**이었지만,
이번 재현 사례의 진짜 원인은 아니었다 — 시간 낭비였다.

**교훈**: 이전 세션의 가설을 이어받을 땐, 그 가설이 "이번 재현 사례"에도
적용되는지부터 확인한다. 타임아웃은 "fetch가 실행됐는데 응답이 안 오는"
경우에만 의미가 있는데, 이번 건은 fetch 자체가 안 나간 경우였다.

### 2. 진단 도구 없이 추측만 반복

"모델이 태그를 안 냈을 것"이라는 가설로 자동 재촉 로직을 먼저 만들었는데,
이것도 정답인지 확인할 방법이 없었다. **원본 응답(태그 포함, 가공 전)을
화면에 그대로 노출하는 진단 패치**를 그제서야 만들었고, 그걸로 순식간에
확정됐다 — 모델이 진짜로 태그를 하나도 안 냈다.

**교훈**: 추측성 수정을 두 번째로 시도하기 전에, 원인을 직접 확인할 수
있는 진단 도구부터 만든다. "쓸데없는 짓 그만하고 정확한 진단부터"라는
지적이 정확했다.

### 3. "새 버전이 있습니다" 배너 반복

짧은 시간에 병합이 몰리면(각 병합마다 버전이 올라감) 자동 새로고침 직후
곧바로 다음 버전을 또 감지해 배너가 반복해서 떴다. 디바운스(3초) +
재시작 쿨다운(20초→90초)으로 고쳤다 — 배포가 몇 분 간격으로 떨어져
있으면 배너가 매번 뜨는 게 정상이고, 그건 버그가 아니다(주피터님도
나중에 이 구분을 직접 확인해 주셨다).

### 4. Cloudflare 엣지 캐시

클라이언트 쪽(캐시 삭제·강제 새로고침)을 아무리 해도 안 바뀌는 경우가
있었다 — hondi.net DNS가 Cloudflare를 거치는데, 그 엣지 캐시가 오래된
파일을 계속 서빙하고 있었다. `Caching → Configuration → Purge Everything`으로
해결. `Browser Cache TTL`(4시간) 설정도 재발 시 용의선상에 있음을 기록.

### 5. GPS `watchPosition`이 GPS 노이즈마다 Kakao 역지오코딩 재호출

hondi-proxy Cloudflare Workers Observability 로그로 발견 — 가만히 서
있어도 GPS 좌표가 소수점 5자리 단위로 흔들리는데, `watchPosition()`
콜백이 매번 조건 없이 `/geocode`를 다시 호출해 45분 넘게 1~3초 간격으로
쉬지 않고 호출됐다. 역지오코딩 호출에만 최소 30초 간격 제한을 걸어 고쳤다
(`services/location.js`).

### 6. 패널에 위치 컨텍스트가 아예 연결돼 있지 않았음

"AC는 항상 사용자 위치를 알아야 한다"는 원칙을 지키는 코드
(`_waitForLocationReady`/`_buildLocNote`)는 메인 채팅에는 있었지만, 패널은
그 모듈을 import한 적조차 없었다. 그래서 "위치를 모른다"는 AI의 답은
거짓말이 아니라 사실이었다 — 코드가 정보를 아예 안 넘겨줬다.

### 7. #message-list가 2026-07-07부터 숨겨져 있었다는 사실 자체

CSS 주석에 답이 있었다: `/* 2026-07-07: AI 비서 대화창이 디폴트가
되면서 이 메인 대화창은 화면에서 숨긴다. */` — 이게 오늘 헤맨 근본
원인이다. "메인 채팅"이라 부를 만한, 실제로 보이는 대안 화면이 애초에
없었다. 패널이 "테스트 버전"이라는 이름표를 달고 있었을 뿐, 실제로는
유일한 프로덕션 화면이었다.

## 오늘 패널에 새로 연결된 기능

`webapp.html`의 `_callPanelAI`에 아래를 새로 배선했다 — 전부 call-ai.js의
기존 함수를 그대로 재사용(새로 재구현하지 않음). `_handleGovTaskTags`~
`_handleCreateUnclaimedProfileTag`(leaf 5종)와 이름표 정정은 jejuro님이
독립적으로 먼저 발견·병합했고, 나머지는 이 세션에서 이어 붙였다:

- `_handleGovTaskTags` — 정부 서류 조회·초안 등록·접수·보완요청·실사
  일정·의견 제출·수수료 승인 *(jejuro)*
- `_handleDeptTaskTag` — 부서 간 업무지시 *(jejuro)*
- `_handleKSearchExecutionTag` / `_handleCreateUnclaimedProfileTag` —
  K-Search STEP3 실행(업체·인물 검색 실제 조회) + 미청구 프로필 생성
  *(jejuro)*
- `_handleBalanceCheckTag` — 재무제표 실시간 조회 *(jejuro)*
- `_anchorGovChain` — OpenHash 앵커링(관찰용, fire-and-forget). call-ai.js
  안에서 export되지 않고 있던 걸 이번에 export 추가 *(이 세션)*
- `[AUTH:L1~L3]` 태그 → `_injectAuthConfirmButton` 인증 단계 상향 요구
  *(이 세션)*
- `_klawReview('conversation', null)` — K-Law 백그라운드 상시 감시
  (3초 지연 fire-and-forget) *(이 세션)*
- `handleExpertTag` 호출 시 누락돼 있던 `userText`/`_preTab` 인자 전달
  (이전엔 `handleExpertTag(full)` 한 인자만 넘겨, 미등록 태그 신고와
  탭 재사용이 조용히 무력화돼 있었음) *(이 세션)*
- 위치 컨텍스트(`_waitForLocationReady`/`_buildLocNote`) — 별도 패치(#255)로
  선행 이식 *(이 세션)*
- "AI 메신저 테스트 버전" → "최신 버전" 이름표 정정 *(jejuro, 이 세션과
  동시에 독립적으로 동일한 정정을 적용)*

## 알려진 남은 한계 (범위 밖으로 명시적으로 남겨둠)

- **`handleExpertTag`의 "이전 대화 맥락 인계" 기능은 여전히 메인 채팅의
  `history` 배열을 참조한다.** 패널의 실제 대화는 `_panelHistory`에
  있으므로, 패널에서 전문가 페르소나 새 탭으로 넘어갈 때 "AC와의 이전
  대화 요약"이 비어 있는 채로 넘어간다. 근본 수정에는 `expert-session.js`가
  history 배열을 인자로 받도록 하는 리팩터링이 필요하다 — 다음 세션 과제.
- GUID·닉네임·비서이름·프로필 완성도 신호 등 `call-ai.js._buildEnhancedUserContent`의
  나머지 컨텍스트 항목들은 이번에 손대지 않았다. 위치 하나만 이번 질문
  범위였다.
- 스트리밍 자체(fetch 후보 목록, SSE 파싱, 끊김 재시도)는 여전히 패널과
  메인 채팅이 각자 독립 구현이다 — 완전한 통합은 이번 세션 범위를 넘는
  더 큰 리팩터링이다.

## 재발 방지 체크리스트

1. **새 화면/기능을 만지기 전에 "이게 실제로 프로덕션인지"부터 확인한다.**
   이름표("테스트 버전", "베타" 등)를 코드의 실제 상태로 오해하지 않는다
   — CSS의 `display:none` 여부, 실제 진입 경로를 직접 확인한다.
2. **두 화면이 같은 기능을 두 번 구현하고 있다면, 신호로 받아들인다.**
   `call-ai.js`와 `webapp.html`의 패널처럼 병렬 구현이 존재하면, 한쪽만
   고치고 다른 쪽을 잊는 사고가 구조적으로 반복된다. 가능하면 공유 함수
   재사용(오늘 이식한 6개 핸들러처럼)을 최우선으로 하고, 부득이 따로
   구현해야 하면 "메인 쪽 수정 시 패널도 확인" 같은 체크리스트를 남긴다.
3. **추측성 수정 전에 진단 도구부터.** 원인이 두 가지 이상으로 갈릴 수
   있는 상황(태그 누락 vs 파싱 실패, 캐시 문제 vs 코드 버그)에서는,
   수정을 먼저 시도하지 말고 원인을 직접 구분할 수 있는 증거(원본 응답,
   실제 배포 버전 등)부터 확보한다.
4. **"안 바뀐다"는 보고를 받으면 배포 인프라부터 의심한다.** 캐시(브라우저
   +Cloudflare 엣지)와 Service Worker 버전 갱신 타이밍이 "코드가 안
   고쳐졌다"는 착각을 자주 만든다. 설정 패널의 "현재 버전" 줄로 실제
   로드된 버전부터 확인한다.
5. **연속 배포 중에는 자동화 자체가 신호를 왜곡할 수 있다.** 짧은 간격의
   잦은 병합은 "배너가 반복된다" 같은, 실제로는 정상인 현상을 버그처럼
   보이게 한다 — 병합 간격이 정상 범위인지부터 구분한다.
