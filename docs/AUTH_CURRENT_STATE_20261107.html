1. 한눈에 보기

설계 원칙은 백서와 같습니다. 가입은 폰에서만, PC 로그인은 반드시 폰 승인입니다. 다만 현재 코드에는 이 원칙과 어긋나는 임시 테스트 스위치(SIMPLE_SIGNUP_TEST)가 켜져 있고, PC 로그인 화면이 두 종류(KAuth 팝업, device-link.html)로 나뉘어 있으며, 폐기된 QR 로그인 파일이 남아 있습니다.

4. 오늘(11/07) 드러난 문제

  1. 안내가 모호 — "스마트폰이 없습니다 — 문자로 안내"만 나오고, 무엇을 해야 하는지가 없음.
  2. 폰 구독이 조용히 삭제 — 푸시 서비스가 구독 만료(410)를 알리면 서버가 기기를 지움. 사용자에게 알림이 없고, 복구 메뉴("푸시 알림 재구독")는 설정 맨 아래에 숨어 있음.
  3. 기기 판정이 UA 한 줄 — 알림음 변경 경로가 deviceType을 빠뜨려 unknown으로 덮어쓰던 결함은 PR #943에서 수정.
  4. 폰 분실·교체 복구 경로 없음 — 개인키가 폰에만 있으면 새 폰은 스스로 로그인 불가(백업 키가 있을 때만 복구).
  5. 로그인 UI 이원화 — A(토큰만)와 B(개인키 이전)가 서로 다른 보안 모델.
  6. 원칙과 코드의 불일치 — "PC 가입 불가" 원칙이 임시 스위치로 꺼져 있음.

5. 단순화 안 (목표 상태)

목표
가입폰 전용. 번호 입력 → 문자 OTP → 지갑 생성 → 푸시 구독(mobile) 등록 → 생체인증 등록 → 복구 방법 안내
PC 로그인하나의 화면(KAuth 팝업). 번호 입력 → 폰 푸시 승인 → 토큰. 폰 구독이 없으면 문자 승인 링크로 대체하고 화면이 상태별로 분명히 안내
자가 치유폰이 앱을 열 때마다 구독 점검·재등록. 서버가 구독을 지우면 "알림 만료" 표시를 남겨 로그인 팝업이 정확히 안내
정리QR 로그인 파일 삭제, B(device-link 화면)는 A로 통합 또는 용도 명시, SSO 계열은 용도 문서화

6. 결정이 필요한 것

  1. SIMPLE_SIGNUP_TEST 종료 시점 — 끄면 PC 가입 차단·생체인증 등록이 복원되고, 서버 SIMPLE_AUTH_TEST도 지워야 테스트 계정 입장이 사라집니다. 테스트 사용자 영향이 있어 시점 결정 필요.
  2. PC에 개인키를 둘지(key_transfer) — A만 쓰면 PC에는 키가 없고 매번 폰 승인(토큰 30일 유지). B를 유지하면 PC가 키를 보관합니다. 이는 PDV를 폰·PC·클라우드에 어떻게 저장할지와 직결되므로 그 논의와 함께 정하는 것이 좋습니다.
  3. 분실·교체 복구 방식 — 복구 코드(가입 시 1회 표시), 지문(WebAuthn)으로 새 기기 승인, 본인 확인 후 초기화 중 선택.

한계: Cloudflare Worker 환경변수(SIMPLE_AUTH_TEST 등)와 운영 서버 응답은 이번 환경에서 접근하지 못해 확인하지 않았습니다.
