### 1-1. 신설 노드

- **`SP-NAT-GOVPLATFORM`** — 정부24가 여러 부처 데이터를 통합해 보여주는 "범부처 자체서비스"(하이패스 미납요금, 요금감면일괄, 미환급금 신청, 지원결정통지 출력, 1372 소비자상담센터 등)를 위한 노드. `SP-NAT-EDUCERT`(대학 증명서용, 2026-09-14 이전 세션 신설)와 동일한 설계 원칙 — domain/도코드를 의도적으로 비워, `_fetchNatText()`가 자동으로 정직한 "[정보 없음] ... 정부24(gov.kr) 또는 110으로 확인" 폴백을 태우게 한다. 존재하지 않는 "제주 지역 사무소"를 지어내는 대신, 있는 그대로 안내하는 게 목적.

### 1-2. 키워드/구조 수정 (커밋 순서대로)

1. `SP-NAT-EDUCERT`에 `검정고시` 추가 (batch3, "검정고시 합격증명서"가 EMD로 낙착되던 것 수정 → **batch5에서 즉시 재현 확인, 0회 호출로 정상 매칭**)
2. `SP-NAT-LABOR`에 `보험 가입 증명원` 추가 (batch3, 근로복지공단 보험가입증명원 갭)
3. `SP-AGY-LIBRARY`의 bare 키워드 `어린이`를 `어린이 열람실`/`어린이 프로그램` 복합어로 교체 (batch4, "어린이집 입소 대기 신청"이 "어린이집"의 "어린이" 서브스트링과 우연히 겹쳐 도서관으로 오확정되던 문제. 2026-08-21에 이미 같은 클래스의 버그(`"어린이집 보육료 지원"` 사례)가 발견돼 L2 후보 병합이라는 구제 경로는 만들어졌었지만, **원인이 된 bare 키워드 자체는 그때 안 고쳐져 있었다** — 오늘 원인을 마저 제거)
4. `SP-NAT-CUSTOMS`에 `관세 납세증명서` 복합어 추가 (batch5, "관세 등 납세증명서"가 `SP-NAT-TAX`의 `납세증명서`와 동점이 되면서 배열 순서상 국세청으로 오확정되던 문제. `_scoreMatchTies()`가 "매칭된 키워드 개수"로 점수를 매기고 동점 시 배열에 먼저 나온 엔트리를 고르는 구조적 특성 — 근본 설계는 그대로 두고 이 특정 충돌만 복합어로 해소)

### 1-3. 테스트 인프라 자체 수정 (`gov24_corpus_live_smoketest.mjs`)

라우팅 로직과 무관하게, **테스트 스크립트 자체가 batch3 중간에 무한정 멈추는 장애**가 발생해 3단계에 걸쳐 원인을 좁혀나갔다(2절 참고). 최종적으로:
- classifyFn 호출에 20초 타임아웃 + 최대 3회 재시도 로직 도입 (기존에는 타임아웃이 전혀 없어 프록시/DeepSeek 응답이 늦으면 스크립트 전체가 영구 정지)
- 재시도 3회 모두 실패하면 `NONE` 처리 후 다음 시나리오로 진행 — 이제 어떤 이유로든 개별 호출이 막혀도 배치 전체가 끝까지 완주한다.

## 2. 무한대기 장애 — 원인 규명 3단계 (중요, 재발 시 참고)

batch3 실행 중 `gov24-b3-002`("한부모가족 증명서 발급받고 싶어요")에서 스크립트가 완전히 멈추는 현상이 발생했다. 코드 버그처럼 보였지만, 실제로는 **세 가지 서로 다른 원인 후보를 순서대로 배제해나가며 진짜 원인에 도달**했다 — 다음에 비슷한 증상이 재현되면 이 순서를 그대로 따라가면 된다.

### 2-1. 1차 가설(기각): Node/undici의 keep-alive 커넥션 버그
- 근거: 첫 항목(item 1)의 fetch는 성공하고, 그다음 fetch부터 멈춤 → "커넥션 재사용 문제"로 의심.
- 조치: `keepalive: false` + `Connection: close` 헤더 추가.
- 결과: **효과 없음.** 재현 지속.

### 2-2. 2차 가설(기각): DeepSeek 백엔드 자체 지연(당일 문서화된 "GPS 역지오코딩 폭주" 사고)
- 근거: `worker.js` 6446번째 줄 주석에 "2026-09-14 GPS 역지오코딩 폭주로 /deepseek이 20~60초까지 지연됐던 사고"가 실제로 기록돼 있었음(이 사고 자체는 오늘 오전 07:57 UTC `a097dd44` 커밋으로 이미 스로틀 수정·배포 완료된 상태였다 — `location.js`의 `watchPosition` 콜백이 GPS 드리프트만으로도 초당 1회꼴로 Kakao 역지오코딩을 재호출하던 버그).
- 조치: 타임아웃을 45초→90초로 상향해 지연 범위를 여유 있게 흡수하려 함.
- 검증: `wrangler tail hondi-proxy`로 실측한 결과, **취소 시점이 26초(`wallTimeMs: 26161`, `cpuTimeMs: 1`)로 우리가 건 45초 타임아웃보다 훨씬 이른 시점**에 이미 `outcome: "canceled"`가 찍혀 있었다 — 즉 우리 코드의 타임아웃이 발동한 게 아니라 그 이전에 이미 연결이 끊겨 있었다는 뜻. 90초 상향은 애초에 발동할 기회조차 없었을 것.
- 추가 검증: `wrangler tail --search "/geocode"`로 GPS 역지오코딩 트래픽 자체가 지금 이 순간엔 0건임을 확인 — 스로틀이 정상 작동 중이고, 이건 현재 진행 중인 원인이 아니었다.

### 2-3. 최종 원인(확정): 클라이언트 측 네트워크 경로의 idle 커넥션 타임아웃
- 근거: 위 wrangler tail 로그의 `cpuTimeMs: 1`은 워커가 DeepSeek 응답을 그냥 기다리며 아무 일도 안 하고 있었다는 뜻이고, `wallTimeMs: 26161`에서 딱 끊긴 패턴은 전형적인 **공유기/ISP NAT의 idle TCP 연결 자동 종료**(데이터 흐름 없는 연결을 25~30초 안에 강제 종료하는 소비자용 NAT 장비의 흔한 동작) 시그니처와 일치한다. 사용자 ISP는 로그에 "KCTV JEJU BROADCASTING"으로 찍혀 있었다.
- **왜 지금까지 몇십 회 테스트에서 한 번도 안 나타났는가**: DeepSeek 응답이 항상 몇 초 안에 왔기 때문에, 원래부터 있었던 이 NAT 특성이 발동할 기회 자체가 없었다. 즉 근본 원인은 두 가지가 겹친 것 — ① 오늘 실제로 DeepSeek(또는 그 경로) 응답이 이례적으로 느려진 사건이 있었고(구체 원인은 미확정 — GPS 폭주는 이미 배제됨, 남은 가능성은 DeepSeek 자체의 지역적/일시적 지연), ② 그 지연이 사용자 네트워크의 잠재적 NAT 한계(약 26초)를 처음으로 실제 초과하면서 "완전히 멈춤"으로 표면화됐다.
- DeepSeek 공식 상태 페이지(status.deepseek.com)는 "Everything is running smoothly", `active_changes: []`로 확인 — 공식적으로 보고된 장애는 없었다. 다만 오늘 DeepSeek이 "V4 Pro API 서비스를 9월 14일 이후에도 계속 제공하기로 결정했다"는 공지가 같은 날 있었던 것도 확인됨 — 서비스 지속 여부 관련 공지 시점과 겹친 정황은 있으나 인과관계까지는 확정하지 못함.
- **최종 대응**: 원인 자체(외부 네트워크 조건)는 우리가 고칠 수 없으므로, "90초 기다리기"에서 "**20초로 짧게 끊고 최대 3회 재시도**"로 전략을 전환. NAT가 끊기 전(약 26초) 안쪽에서 매번 새 연결로 재시도하면, 간헐적 지연 상황에서도 어느 한 번은 응답을 받을 확률이 올라간다. 3회 모두 실패해도 `NONE` 처리 후 다음 시나리오로 넘어가므로 더 이상 스크립트 전체가 멈추지 않는다.

**교훈**: "무한정 멈춤" 증상은 항상 여러 계층(우리 코드 / 우리 인프라 워커 / 외부 API 백엔드 / 사용자 로컬 네트워크 경로)에 걸쳐 있을 수 있고, 로그 없이 추측만으로 상위 계층부터 고치려 하면 헛수고가 반복된다. `wrangler tail`의 실제 타임스탬프·`cpuTimeMs`·`outcome` 필드를 직접 대조해서야 진짜 원인(가장 바깥쪽 계층인 로컬 네트워크)에 도달할 수 있었다.

## 3. 아직 손대지 않은 관찰 사항 (다음 세션 참고용)

우선순위 순으로, 확신도와 함께 정리한다. 전부 "발견했지만 이번 세션에서는 수정하지 않음" 상태다.

### 3-1. 확신도 높음 — 반복 관찰된 시스템적 불일치

- **식품영업 관련 부서 4-way 분산**: "식품관련영업신고"(b4-015→WELFARE), "식품영업 신고"(b4-036→BOHWAN), "건강기능식품 영업신고"(b5-022→SAFETY), "식품 영업신고증 재발급"(b7-038→WELFARE), "건강기능식품판매업 폐업신고"(b7-029→SAFETY) — 같은 유형(식약처 소관 영업신고류)이 매번 다른 도(道) 부서로 흩어진다. 각 요청이 LLM 5회 호출(폴백)을 거치는 걸 보면 결정론적 키워드 매칭이 아니라 매번 LLM이 새로 판단하고 있다는 뜻 — 후보 목록에 이 영업신고류를 명확히 담당하는 부서가 두드러지지 않는 것으로 추정. **다음 세션 조치안**: 이 5개 do-dept 후보(WELFARE/BOHWAN/SAFETY/...) 중 하나를 "식품위생" 키워드로 명시적으로 고정하거나, 최소한 같은 표현("영업신고", "폐업신고" 등)에 대해서는 결정론적 매칭이 되도록 키워드를 보강해야 한다.

- **고용노동부 휴가·급여 제도가 LABOR/WELFARE 사이에서 갈림**: "가족돌봄휴직"(b3-046→`SP-NAT-LABOR`, 0회) vs "육아휴직 급여 신청"(b4-004→`SP-DO-WELFARE`, 4회) vs "출산전후휴가 급여등"(b7-009→`SP-DO-WELFARE`, 1회) vs "생리휴가 제도"(b5-045→`SP-NAT-LABOR`, 5회) — 전부 고용노동부 소관 근로자 휴가/급여 제도인데 국가기관(LABOR)과 도 복지부서(WELFARE) 사이를 오간다. 근본적으로는 "이 유형의 제도는 어디로 보내는 게 맞는가"에 대한 설계 결정이 필요해 보인다(고용보험 급여 계열은 LABOR로 통일하는 것을 제안).

- **"가격확인서" 계열이 부서마다 흩어짐**: 개별공시지가 열람(b5-019→시청 건축과), 개별주택가격 확인서(b6-048→PLAN), 전국 주택 가격 동향 조사(b5-015→HOUSING) — 개념적으로 인접한 문서들이 PLAN/HOUSING/시청건축과 세 곳으로 갈린다.

### 3-2. 확신도 중간 — 개별 오분류 후보 (재현/추가 검증 필요)

- **"국방 X" 계열이 반복적으로 EMD 낙착**: 국방 헬프콜 1303(b6-008), 국방 증명서 발급 서비스(b6-012), 교직원 온라인 채용(b6-006) — MND 정책기관 노드(`SP-POLICY-LAZY(MND)`)가 이미 존재하고 다른 예비군·병역 관련 발화는 잘 매칭되는데, 이 표현들만 LLM이 못 잡는다.
- **"나이스/디지털교과서" 계열 교육 디지털서비스**: 나이스 학원 민원(b4-050), 학술연구정보서비스 RISS(b5-029), 대입정보포털(b5-046) — `SP-NAT-EDUCERT`가 이미 "나이스플러스"·"나이스 학부모서비스"는 LLM으로 잡아내는데 이 세 건은 실패. 발화 표현이 조금씩 다를 뿐 개념적으로는 동일 카테고리.
- **b7-045** "휴업 및 폐업 신고"(국세청 소관, `SP-DO-ECON`로 감) — 이미 `SP-NAT-TAX`에 `폐업사실증명`이 bare 키워드로 있는데, "신고"(사실 확인이 아니라 절차)라는 표현으로 바뀌자 다른 부서로 샜다.
- **b5-002** "동력수상레저기구 조종면허"(해양경찰청 소관) → `SP-NAT-PORT`로 감. 이미 존재하는 `SP-NAT-COASTGUARD`가 더 정확해 보임.
- **b5-012** "운전적성정밀검사"(교통안전공단) → `SP-NAT-LABOR`로 감. 다른 운전면허 관련 건은 전부 POLICE로 가는데 이것만 LABOR — LLM의 명백한 오판.
- **b5-038** "승무경력 증명서"(해양수산부, 선원 경력) → `SP-NAT-EDUCERT`로 감. 학교 증명서가 아닌데 EDUCERT로 갔다.
- **b4-041 vs b3-026**: 거의 동일한 발화("안심상속 원스톱서비스")가 한 번은 `SP-NAT-GOVPLATFORM`, 한 번은 `SP-DO-WELFARE`로 갈렸다 — LLM 판단 편차. (참고: b7-049에서 동일 발화가 다시 GOVPLATFORM으로 정상 매칭된 것도 확인 — 재현율이 100%는 아니라는 뜻.)

### 3-3. 확신도 낮음 / 정책 판단이 필요한 것

- "사실증명" 단독 발화(b6-023, b6-031, b2-035 등)처럼, **정부24 원본 명칭의 괄호 안 세부사항("사업자등록사실여부" 등)이 실제 사용자 발화에는 아예 안 들어있는** 저맥락 케이스들이 여러 건 반복 관찰된다. 이건 라우팅 로직의 결함이 아니라 **테스트 시나리오 자체가 원본 정부24 항목명을 간소화하면서 핵심 구분 정보를 날려버린 것**에 가깝다(professor-gap-14와 동일 클래스, 2026-09-14 세션에서 이미 이 원칙으로 검토·확정한 바 있음). 시나리오 재생성 시 괄호 안 내용을 발화에 자연스럽게 녹이는 방향을 고려할 만하다.
- 니치 국가기관·공기업(중소벤처기업진흥공단, 인사혁신처, 한국전력공사, 한국언론진흥재단, 국민체육진흥공단 등)에 대한 대응 노드 부재로 인한 EMD 낙착 다수 — `SP-NAT-GOVPLATFORM` 확장으로 흡수할지, 개별 노드를 늘릴지는 향후 물량을 보고 판단.
