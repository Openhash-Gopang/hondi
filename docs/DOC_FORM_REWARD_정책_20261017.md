# 서식 공유·평가·GDC 보상 — 정책과 알고리즘 (2026-10-17)

> 주피터님 지시: 모든 전문직에서, 어느 이용자가 서식을 추가하면 다른 이용자가 활용할 수 있음을 알리고, **처음으로 서식을 추가했고 다른 이용자들이 그 서식의 유용성을 높이 평가한 이용자**에게 GDC를 지급한다.
> 구현: `src/worker/doc-form-reward.js`(규칙·핸들러), `doc-form-reward-store.js`(PocketBase 어댑터), `pb_migrations/1794900001·1794900002`, 화면 `pages/expert-chat.html`·`assets/expert-shared-forms.js`, SP `SP_DOC_FORM v1.3`.
> 규칙 수치의 정본은 코드(`REWARD_RULES`)이며, 테스트(`doc-form-reward.test.mjs`)가 이 문서의 값과 같은지 확인한다.

## 1. 흐름

```
이용자 A가 전문가 채팅에서 서식을 첨부 → 빈 서식으로 정리 → 저장 동의 카드
  └ 카드에 고지: ① 이 직역 전문가 페이지에 게시되어 다른 이용자가 활용 ② 처음 올린 서식은 조건 충족 시 GDC 보상 가능(보장 아님)
  └ A가 동의·지갑 서명 → doc_forms 에 v1 저장 (기존 기능)
      ↓
전문가 페이지(/pages/<직역>.html)의 「이용자가 알려 준 서식」 목록에 게시 (7일간 "새 서식" 표시, 평가 요약 표시)
      ↓
이용자 B가 채팅에서 서식 이름을 말함 → 서식 DB 조회 → 그 서식으로 서류 작성
  └ 작성 후 평가 카드(1~5점) — B가 점수를 누르면 지갑 서명으로 /doc-form/rate
      ↓
평가가 들어올 때마다, 그리고 A가 「내 서식 현황」을 열 때마다 서버가 지급 조건을 점검(settle)
  └ 조건 충족 + env.DOC_FORM_REWARD_KRW > 0 → L1 /api/mint (memo form_reward:…) 로 A에게 지급
```

## 2. 규칙 (정본: `REWARD_RULES`)

| 항목 | 값 | 이유 |
|---|---|---|
| 보상 대상 | 어떤 서식(key_hash)의 **version 1 기여자**만 | "처음으로 추가". 개정본(v2~) 기여자는 대상 아님 |
| 보상 대상 출처 | `user_attached`(이용자가 실제 서식을 가져온 것)만 | AI가 지어낸 서식으로 보상을 받는 것을 막음 |
| 기본 보상 조건 | 인정 평가자 5명 이상 · 보정 평균 4.0 이상 · 4~5점 비율 70% 이상 | 소수 평가의 우연·편중 방지 |
| 우수 보상(같은 액수 1회 추가) | 인정 평가자 20명 이상 · 보정 평균 4.5 이상 · 4~5점 비율 85% 이상 | |
| 보정 평균 | (점수 합 + 3×2) ÷ (평가 수 + 2) | 적은 표에서 5점 몇 개로 올라가는 것 완화 |
| 인정 평가 | 가입 7일 이상 계정 · 본인 서식 아님 · 상호 평가 아님 · 이용자당 서식 1표(고쳐 쓰면 덮어씀) | 여러 계정·품앗이 평가 방어 |
| 지급 대기 | 저장 후 72시간 | 담합·오남용 점검 시간 |
| 한도 | 평가자 하루 30건 · 기여자 30일 10건 | |
| 제외 | 운영자(`DOC_FORM_ADMINS`)가 올린 서식 · 같은 본문이 다른 서식으로 먼저 저장된 경우 | |
| 지급 금액 | `env.DOC_FORM_REWARD_KRW`(원 상당, 1:1). **0이거나 없으면 지급하지 않고 평가·집계만** | 금액·시행 시점은 운영자가 정함 |
| 멱등 | (key_hash, version, kind) 유일 | 같은 보상 이중 지급 방지 |
| 실패 처리 | L1이 명시적으로 거절 → `failed`, 5분 간격 최대 3회 자동 재시도. 응답을 못 받음 → `unknown`, 운영자 확인 전 재시도 안 함 | 이중 지급보다 지급 지연을 택함 |

공개 응답(목록·집계)에는 기여자·평가자 식별자가 없다. 평가자에게는 지급 여부를 알리지 않는다.

## 3. 운영 절차

1. PocketBase 마이그레이션 적용(`doc_form_ratings`, `doc_form_rewards`).
2. 배포 후에는 **평가·집계만 동작**하고 지급은 꺼져 있다.
3. 지급을 켜려면 `wrangler secret put DOC_FORM_REWARD_KRW`(또는 vars)에 금액을 넣는다. 켠 뒤에는 이미 조건을 채운 서식도 다음 점검 때 지급된다(소급).
4. 이상 징후: `/doc-form/reward-admin`(운영자 서명)으로 `void`(무효) 또는 `retry`(L1 원장에서 지급되지 않았음을 확인한 `failed`/`unknown` 건 재시도). `paid`·`minting`은 바꿀 수 없다.
5. 로그 태그 `DOC_FORM_REWARD_PAID`, 오류 `[DocFormReward]`.

## 4. 남은 위험 (구현으로 막지 못하는 것)

| 위험 | 현재 방어 | 남는 위험 |
|---|---|---|
| 여러 계정으로 자기 서식에 5점 | 가입 7일 이상, 서명, 하루 30건, 상호 평가 제외, 72시간 대기 | 7일 전에 미리 계정을 만들어 두거나, 서로 모르는 척하는 3자 이상 순환 평가는 탐지하지 못한다. 가입 시 지급되는 무료 GDC 때문에 계정 생성 비용이 낮을 수 있다. 지급액이 커지면 평가자 본인확인(전화 인증 등) 조건을 추가해야 한다 |
| 쓰지 않고 점수만 누름 | `used:true` 자기 선언, 서명 | 서버는 실제 사용 여부를 확인하지 못한다 |
| 서식명을 바꿔 "처음"을 가로챔 | 같은 본문(body_hash) 선행 저장 시 제외 | 공백·문장부호만 다른 본문은 다른 서식으로 취급된다 |
| 이미 공개된 서식을 올려 보상 | 없음 | "처음으로 서식 DB에 추가"를 보상 기준으로 삼은 것이므로 의도된 동작이다. 공식 서식 복사만으로 보상받는 것을 막으려면 운영자 검토(`reviewed`) 이후에만 지급하도록 바꿀 수 있다 |
| mint 이중 지급 | 유일 인덱스, `minting`/`unknown` 상태 보호 | 동시 요청 두 개가 같은 `failed` 건을 재시도하는 극히 좁은 구간(5분 간격 검사)은 남는다 |
| 통화 정책 | — | 보상은 L1 `/api/mint`로 **신규 발행**된다(가입 축하 충전과 같은 경로). 총발행·인플레이션 상한(GDC_POLICY)과의 관계는 운영 결정이다 |
