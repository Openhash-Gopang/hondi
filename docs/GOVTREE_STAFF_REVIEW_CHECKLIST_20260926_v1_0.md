## 이 문서를 쓰는 법

각 SP 파일 상단의 `# 정직하게 밝힘` 주석과 §6(유의사항)에 이미 "확인하지 못함"·
"재검증 필요"가 구체적으로 적혀 있다. 이 문서는 그걸 부서별로 한 곳에 모아,
**실제 담당자가 파일을 열지 않고도 무엇부터 확인해야 하는지** 알 수 있게 한
요약표다. 확인 후 고칠 내용이 있으면 해당 SP 파일(`prompts/gov-tree/...`)을
직접 수정하고, 버전 번호를 올리고(`_v1.0.md` → `_v1.1.md`), 파일 상단 변경
이력에 확인 주체·일자를 남겨주면 된다.

## B. 소방서 현장단위 SP 31개 — 별도 주의

`prompts/gov-tree/03-do-agency/divisions/field-units/` 아래 31개 파일
(119안전센터·구조대·지역대 단위)은 이번 세션에서 프로젝트 총괄의 명시적
지시("현장 단위까지 수십 개 SP를 작성하십시오")로 신설했다. 근거 자료
자체가 부족해(별표에 개별 현장단위 사무 구분이 없음) **거의 전부 기관·
현장단위 명칭 기반 추정**으로 작성됐다 — 이 문서군이 confidence 등급 중
가장 낮다.

- 4개 소방서(제주·서귀포·서부·동부) × 소방행정과/예방(안전/구조)과/
  119재난대응과/현장대응단 아래 각각의 안전센터·구조대·지역대.
- **가장 필요한 확인**: (1) 관할 구역이 실제와 맞는지(읍면동 경계 변경
  가능성), (2) 명칭이 최신인지(통폐합·신설), (3) 대표번호(119 긴급신고
  번호가 아니라 비긴급 행정 문의용 대표번호)가 실제로 존재하고 맞는지.
- 이 SP들은 시민 응대용 라우팅에 실제로 연결돼 있으므로(division-tables.js
  `JEJU_AGENCY_DIVISION_TABLE`), 관할·명칭이 틀리면 시민이 엉뚱한 안내를
  받을 수 있다 — 확인·수정의 우선순위가 A그룹보다 높을 수 있다.

## 확인 후 반영 방법

1. 위 표에서 확인이 끝난 항목은 해당 SP 파일의 §1(정체성)·§LEGAL-BASIS·§2를
   직접 수정한다.
2. 파일명 버전을 올린다(`_v1.0.md` → `_v1.1.md`, 파일명이 division-tables.js
   의 `file` 필드와 정확히 일치해야 라우팅이 깨지지 않는다 — 파일명을 바꿨다면
   `division-tables.js`의 해당 `file` 값도 같이 바꿔야 한다).
3. 파일 상단 "버전 변경 이력" 섹션에 확인 주체(부서명)·일자·변경 내용을
   한 줄로 남긴다.
4. 라우팅 키워드(`kw`)를 실제 업무 명칭에 맞게 추가·수정했다면, 수정 후
   `python3 tools/check_stale_refs.py`와 `node tools/build_kfoi_digest.mjs
   --check`를 실행해 깨진 참조가 없는지 확인한다(개발팀에 요청해도 된다).
