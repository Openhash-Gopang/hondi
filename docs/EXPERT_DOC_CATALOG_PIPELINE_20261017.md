# 전문가 페이지 서류 목록 — 구조와 갱신 절차 (2026-10-17)

> 주피터님 지시: 모든 전문가 페르소나 페이지에 "작성 문서 목록"을 갖춘다. 서류 작성은 **PC 화면**을 기본으로 보고, 모바일은 상담·질의·업무 지시용으로 본다. 의사 등 모든 직역에서 **AI가 쓸 수 없는 서류를 따로 두지 않는다** — 이용자는 전문가 본인이고, AI는 그 지시로 초안을 쓴다(최종 확인·서명은 전문가).
> 진행 상황: [`research/서류목록_조사_진행표.md`](./research/서류목록_조사_진행표.md)

## 1. 목록형 페이지가 동작하는 방식

서류 목록형 페이지는 **목록**과 **SP(프롬프트)** 두 가지가 짝으로 있어야 한다.

| 구성 | 위치 | 하는 일 |
|---|---|---|
| 서류 목록 데이터 | 페이지의 `window.PRO_DOC_PAGE`(`catalog`) | `assets/pro-doc-page.js`가 탭·표·「대화로 작성」 버튼으로 그린다 |
| 서류 목록 정본 | SP의 `## 부록 A` | 업무 영역(`### A-n. 제목 (제출처·근거)`)별 표 |
| 서식 출력 규격 | SP의 `C-2. 서식 출력 규격` | AI가 서류를 front matter(`doc_type:` 포함)가 있는 코드펜스 하나로 출력하게 한다 |
| 작성된 문서 | `pro-doc-page.js`의 `transformReply` | 답변에서 `doc_type:`이 있는 문서를 뽑아 「작성된 문서」 카드에 옮기고 웹 표준 서식 파일로 내려받게 한다 |

C-2가 없는 SP로는 목록만 보이고 「작성된 문서」가 작동하지 않는다. 그래서 목록형으로 바꿀 직역의 SP에는 **부록 A와 C-2를 함께** 넣는다.

## 2. 단일 원본 — SP 부록 A → 페이지

- **생성 페이지**(`scripts/gen-expert-pages.py`가 만든 페이지): SP에 부록 A와 C-2가 있으면 목록형으로, 없으면 입력창만 있는 페이지로 만든다. 목록은 SP 부록 A를 읽어 만든다. **직역 하나를 끝내는 작업 = SP 갱신 + 생성기 실행**이다.
- **수작업 페이지**(기존 16개: 회계사, 행정사, 감정평가사, 건축사, 관세사, 전기안전기술자, 소방안전관리자, 가스안전기술자, 산업안전지도사, 노무사, 조경기술자, 손해사정사, 변리사, 부동산중개사, 측량기술자, 세무사): 페이지 데이터를 직접 갖고 있다. 탭 이름은 페이지가 줄여 쓸 수 있지만, 항목·설명·안내·제출처 표시는 SP와 같아야 한다 — `B-05` 테스트가 확인한다.
- 법무사 페이지는 자체 방식이라 이 검사 대상이 아니다.

### 부록 A 작성 형식 (생성기가 읽는 형식)

```
## 부록 A — {직역} 서류 카탈로그
### A-1. {업무 영역} ({제출처·근거 등 한 줄})
소개 문단(선택, 유의 표시가 없으면 그 탭의 소개가 된다)
**유의**: 주의 문장(선택, 여러 줄 가능)
| 서류 | 핵심 기재 · 첨부·확인 |      ← 2열: 둘째 열이 설명
|---|---|
| 서류 이름 | … |
```

- 표가 3열 이상이면 `헤더: 값`을 ` · `로 이어 설명으로 쓴다. 표 대신 `- **서류**: 설명` 목록도 쓸 수 있다.
- 헤더 뒤의 `— form_class A` 표시는 탭 이름에서 빠진다. 서류가 하나도 없는 절(예: "이 부록에 없는 서류")은 탭이 되지 않는다.
- 이 규칙은 `parse_catalog()`(`scripts/gen-expert-pages.py`)가 정본이며, `python3 scripts/gen-expert-pages.py --catalog-json <SP 파일>`로 어떻게 읽히는지 볼 수 있다.

## 3. 직역 하나를 갱신하는 절차

1. **조사**: 근거 법령, 법정 서식(별지 번호), 제출처, 기한을 웹에서 확인한다. 원문 확인 수준을 서류마다 표시한다 — 원문 확인 / 정리본 기준 / 미확인. 번호나 칸 구성을 지어내지 않는다. 조사 결과는 `docs/research/<직역>_서류_조사_<날짜>.md`에 남긴다.
2. **SP 갱신**: 새 버전 파일(`SP_<직역>_vX_Y.md`)에 부록 A와 C-2를 추가한다. 순수 추가만 하고 기존 줄은 지우지 않으며 상위 규칙(§LEGAL-LIMIT 등)은 완화하지 않는다. `sp-catalog.json`·`sp-catalog-categories.json`·`pages/expert-personas.html`·`pages/professional-ai.html`·`data/expert-persona-index.json`의 참조와 `src/tests/sp_klaw_v151_hooks.test.js`(해당 직역 항목)를 새 파일명으로 옮긴다.
3. **페이지 생성**: `python3 scripts/gen-expert-pages.py` — 해당 직역 페이지가 목록형으로 바뀐다.
4. **검사**: `node --test src/tests/expert_pages_start_field.test.js src/tests/sp_klaw_v151_hooks.test.js` 와 `python3 tools/check_stale_refs.py`.
5. **진행표 갱신**.

## 5. 남은 일과 알려진 한계

- 도선사 페이지의 서류 목록은 도선법·시행규칙 **정리본 기준**이다. 법제처 원문과 대조하지 않았다.
- 생성된 목록형 페이지에는 수작업 페이지에 있는 "관계 법령" 표가 없다(SP에서 읽을 형식이 아직 없음). 필요하면 부록 A 앞에 법령 표 형식을 정하고 생성기에 추가한다.
- 나머지 입력창만 있는 페이지 125개와 기존 목록형 17개의 내용 재조사는 진행표대로 직역별로 이어간다.
- 서식 DB(`SP_DOC_FORM`: 이용자가 올린 서식)와 이 목록은 별개 메커니즘이다. 목록은 "어떤 서류를 쓸 수 있는가"를, 서식 DB는 "그 서류의 칸 구성"을 담당한다. C-2의 `form_source`가 그 연결 고리다.
