## 1. 목표

1. **`desktop.html` 사이드바에서 일반 사용자와 개발자가 서로 다른 문서
   목록을 본다**는 확신이 들도록 구조를 분리한다.
2. 일반 사용자용 문서 3종의 **품질 결함 5가지**(§0.2)를 고친다.
3. `MANUAL_INDEX.md`를 **순수 개발자용 인덱스**로 재정의하고, 일반
   사용자는 별도의 진입점(§3.2)으로 안내한다.
4. 기존에 이미 잘 돼 있는 것(탐색 섹션, 개발자 문서 콘텐츠 자체의
   내용 품질)은 건드리지 않는다 — 이번 작업은 **재배치와 결함 수정**이지
   전면 재작성이 아니다.

## 2. 원칙

1. **콘텐츠를 새로 쓰지 않고 재배치한다.** §0.2의 3개 문서는 이미 품질이
   높다 — 구조를 갈아엎지 않고, 발견된 결함만 국소 수정한다.
2. **`docs/` 폴더의 186개 파일 전체를 정리하지 않는다.** `MANUAL_INDEX.md`가
   이미 큐레이션한 ~25개 "진짜 매뉴얼"만 이번 재구성 대상이다. 나머지
   161개(설계안·작업기록·인시던트 보고서 등)는 `MANUAL_INDEX.md`가 이미
   적절히 분류해뒀고, 그 자체가 "개발자만 필요시 찾아보는 것"이라는
   합의가 이미 있다(📝 작업 이력, 📦 아카이브 카테고리).
3. **파일을 옮기지 않고 링크만 재배치한다(1단계는).** `docs/*.html`·`*.md`
   파일 경로 자체를 바꾸면 기존에 이 파일들을 직접 참조하는 다른 곳
   (README, 다른 매뉴얼의 상호 링크 등)이 깨질 위험이 있다 — 실제로 옮길
   필요가 생기면 별도 단계로 분리한다(§5 2단계 이후).
4. **일반 사용자는 "개발자 문서" 섹션 존재 자체를 몰라도 아무 지장이
   없어야 한다.** 반대로 개발자는 필요하면 일반 사용자 문서도 쉽게 찾을
   수 있어야 한다(개발자가 일반 사용자 시나리오를 이해해야 할 때가
   있음) — 즉 **일방향 숨김이 아니라 우선순위 분리**다.

### 3.2 `MANUAL_INDEX.md` 재정의

현재 이 문서는 "일반 사용자 대상"·"개발자 온보딩"·"API·인프라 레퍼런스"·
"작업 이력"·"아카이브" 5개 카테고리를 한 표에 담고 있다. **이 문서 자체의
역할을 "개발자용 문서 지도"로 좁히고**, "일반 사용자 대상" 카테고리는
빼낸다 — 대신 그 표 맨 위에 다음 안내만 남긴다:

```markdown
> ℹ️ 일반 사용자 대상 문서(사용자 매뉴얼·시작하기·용어집)는 이 인덱스가
> 아니라 `desktop.html` 사이드바 "📖 이용 안내" 섹션에서 확인하세요.
> 이 문서(`MANUAL_INDEX.md`)는 개발자 온보딩·API/인프라 레퍼런스만
> 다룹니다.
```

이렇게 하면 "개발자가 어쩌다 `MANUAL_INDEX.md`를 열었는데 일반 사용자
안내가 섞여 있어 진짜 필요한 것을 찾기 번거롭다"는 문제와, "일반
사용자가 실수로 `MANUAL_INDEX.md`(개발자 문서 지도)를 열어버리는" 문제를
동시에 줄인다.

## 4. 콘텐츠 결함 수정 (§0.2의 5가지, 우선순위순)

### 4-1. 백업 키 경고 강화 (최우선 — 금전·계정 손실 리스크)

**대상**: `user-manual.html`(루트) "백업 키" 섹션 + `user-guide.html`
"00·시작하기" 흐름.

- `user-guide.html`의 "시작하기" 4단계 흐름에 **"2단계(아이디 입력)와
  3단계(AI 모델 선택) 사이에 백업 키 저장을 별도 단계로 승격**"한다 —
  지금은 이 경고가 아예 시작하기 흐름에 없고 루트 `user-manual.html`에만
  있다. 계정 생성 직후, AI 기능을 켜기 전에 사용자가 반드시 한 번은
  마주치게 만든다.
- 문구 톤은 기존 매뉴얼의 다른 경고("⚠️ 키는 꼭 따로 저장해 두세요")와
  동일한 톤을 유지하되, "찾을 수 있는 곳에 저장"보다 한 단계 더 강하게
  — "이 키를 잃어버리면 그 계정은 아무도(개발팀도) 되찾아드릴 수
  없습니다"까지 명시한다(현재 문구는 이 사실을 설명은 하지만 경고
  수준의 시각적 강조가 약함).

### 4-2. 용어집 신설

**신규 파일**: `docs/hondi_glossary.html`(다른 사용자 문서와 톤·스타일
일치, 확장자 html — 일반 사용자가 열기 쉬운 형식 유지).

포함 용어(§0.2에서 확인된, 사용자 문서 3종에 등장하는 용어 전수):
PDV, AC, GDC, GUID, 개인키/백업 키, OpenHash, K-서비스 목록(K-Law·
K-Tax·K-Health 등), System Prompt, 나비 숫자 코드, LLM, API 키.
각 항목은 **기존 매뉴얼에 이미 있는 비유를 그대로 재사용**한다(새로
비유를 만들지 않음 — 자동차/내비게이션, 이름표/도장, 천 짜기 등
기존 표현과 다른 설명이 새로 생기면 오히려 혼란).

### 4-3. "IPv6 주소" 등 불필요한 기술 노출 정리

**대상**: `user-manual.html` "IPv6 주소 — 웹과의 통합" 섹션.

사용자가 지금 당장 뭘 하지 않아도 되는 내부 구현 세부사항이라, 섹션
자체를 삭제하거나(권장) 개발자 문서 쪽(`01-system-map.md` 등)으로
옮긴다. 삭제해도 사용자 매뉴얼의 다른 어떤 설명도 이 문장에 의존하지
않는다(독립적으로 검증 — 다른 곳에서 "IPv6"를 참조하는 문장 없음).

### 4-4. "달리" 표현 정정

**대상**: `user-guide.html` "01·나비란?" — "나만의 AI 비서(달리,
그림자 AI 비서)".

`user-manual.html`에는 "그림자 AI 비서"라는 표현만 쓰이고 "달리"는
없다 — 다른 두 문서와 대조해 "달리"가 의도된 별칭이 아니라 편집
과정에서 남은 잔여 표현임을 확인 후 제거("나만의 AI 비서(그림자 AI
비서)"로 정정).

### 4-5. "핵심 기능 실패" 문제해결 FAQ 신설

**대상**: `user-manual.html`(루트) — 기존 카메라·마이크·위치 권한
문제해결 섹션과 같은 형식으로 신설.

다룰 항목(전부 §0.2 감사에서 실제 빠져있음을 확인한 것):
- "AI가 대답을 안 해요" — API 키 미등록/오류 확인 순서
- "GDC가 다 떨어졌어요" — 잔액 확인·충전 화면 안내(이미 `hondi_user_manual.html`
  §00-2에 GDC 3문장 요약이 있으므로, 여기서는 "떨어졌을 때 무엇을
  보게 되는지 + 무엇을 누르면 되는지"만 추가)
- "나비 숫자 코드가 인식이 안 돼요" — 이미 있음(기존 섹션 재확인,
  누락 아님)

## 5. 단계·우선순위

이 프로젝트가 계속 유지해온 "작게 쪼개서 검증 가능한 단위로" 원칙을
그대로 따른다.

### 1단계 — 콘텐츠 결함 수정 (§4-1~4-5)
코드 변경 없음, 문서만 수정. 기존 회귀 테스트(`gov-router.test.mjs` 등)와
무관 — 검증은 "실제로 그 문구가 파일에 들어갔는지"를 grep으로 직접 확인.

### 2단계 — `desktop.html` 사이드바 재구성 (§3.1)
링크 재배치만(파일 이동 없음) — 기존 href가 그대로 유효한지 먼저 확인
후 진행. `docs/user-guide.html`을 사이드바에 추가로 노출하는 것도 이
단계에 포함(현재 desktop.html에 링크 자체가 없음).

### 3단계 — `MANUAL_INDEX.md` 재정의 (§3.2)
2단계가 끝나 실제 진입점이 생긴 뒤에 진행 — 순서가 바뀌면 잠깐이라도
"일반 사용자 대상 문서를 어디서도 못 찾는" 공백이 생긴다.

### (범위 밖) 파일 실제 이동·디렉토리 재구성
`docs/` 안에 `docs/user/`, `docs/dev/` 같은 하위 폴더를 만들어 파일
자체를 옮기는 건 이번 계획에 포함하지 않는다 — 원칙 3(파일을 옮기지
않고 링크만 재배치) 참고. 이후 필요성이 확인되면 별도 계획으로 분리.

## 6. 검증

- 1단계: 각 문서 파일에서 grep으로 수정 내용이 실제로 반영됐는지 확인
  (백업 키 강조 문구 위치, 용어집 파일 존재, "IPv6" 문자열 부재,
