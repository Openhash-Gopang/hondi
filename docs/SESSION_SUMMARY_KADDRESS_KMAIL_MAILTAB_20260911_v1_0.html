Overview
이 문서가 왜 있는가

겉보기엔 "CSV 업로드 기능 하나 만들기"였지만, 실제로 손댄 범위는 K-Address 연락처 등록 경로 전체(수동/CSV/대화 저장)와 K-Mail의 새 "메일" 탭, 그리고 그 둘을 잇는 다리까지 걸쳐 있었다. 이 문서는 (1) 지난 세션에서 넘어온 배경, (2) 이번 세션에 실제로 찾아낸 버그 세 가지와 각각의 재발 방지 조치, (3) 새로 만든 기능들, (4) 이걸 검증하는 라이브 스모크테스트까지 순서대로 기록한다. 다음에 K-Address/ K-Mail 영역을 다시 건드릴 사람은 이 문서 하나로 전체 그림을 파악할 수 있어야 한다는 목표로 썼다.

지난 세션(2026-09-10)
165명 벌크 등록 사고와 CSV 업로드 기획 착수

KAIST 전산학부(139명) + AI대학원(26명), 합쳐 165명을 K-Address 대화로 한 번에 등록하려던 시도가 20000토큰 한도로도 부족해 재차 실패했다. SP 지침에 "40건 넘으면 나눠서"가 이미 있었는데도 AI가 이를 무시하고 165건을 한 번에 밀어넣으려 한 것이 원인이었다.

조치는 두 갈래였다: ① 배치 한도를 20000→60000 토큰으로 재상향, ② SP 지침 자체를 "60건 넘으면 반드시 나눠서"로 더 강하게 못박음. 같은 세션에서 K-Address 채팅 UI의 자동 스크롤 버그(긴 메시지를 보내면 로딩 표시·입력창이 화면 밖에 남는 문제)도 함께 고쳤다.

세션 막바지에 "AI 호출 자체가 필요 없는" CSV 업로드 경로를 만들기로 방향을 잡았다 — 이번 세션이 그 완성판이다.

① CSV/엑셀 일괄 업로드
AI를 거치지 않는 순수 REST 등록 경로

POST /kmail/contacts/csv-import 신설 — 프론트엔드가 CSV/엑셀 파일을 직접 파싱해 구조화된 contacts 배열로 보내면, K-Address 대화를 전혀 거치지 않고 그대로 kmail_contacts에 등록한다. 태그 잘림·거짓 완료 서술·배치 크기 초과처럼 AI 호출 특유의 사고가 구조적으로 발생할 수 없는 경로다.

소속명 자동 분류(_kaddressClassifyCategory)는 결정적(deterministic) 키워드 매칭으로 처리한다 — 대학교/ 병원/시청/연구소/협회/은행/방송/대사관 등 키워드 그룹과 이메일 도메인(.ac.kr/.go.kr/.re.kr/.or.kr) 폴백, 무매칭 시 빈 값 유지. "대학병원"처럼 키워드가 겹치는 경우를 위해 의료(Q) 그룹을 교육(P) 그룹보다 먼저 검사한다.

② 실사 발견 버그
category가 select 필드인데 코드 한 글자만 넣던 문제

kmail_contacts.category는 자유 텍스트가 아니라 PocketBase select 필드로, 21개 고정값 ("P 교육 서비스업"처럼 코드+정식명칭이 붙은 문자열) 중 정확히 하나만 허용한다. 그런데 첫 구현은 'P'처럼 코드 한 글자만 넣고 있었다 — 값이 select 옵션과 정확히 일치하지 않으면 레코드 생성 자체가 조용히 실패한다.

실사 사례
767명짜리 KAIST/법학전문대학원/제주대 CSV를 업로드했는데 실제 DB엔 8건(영문 소속이라 키워드가 안 걸린 것들)만 남고 나머지가 흔적도 없이 사라졌다. 화면에는 "완료"만 뜨고 실패 원인을 알 방법이 없었다 — handleKmailContactsCsvImport가 개별 레코드 생성 실패를 전혀 로그하지 않았기 때문이다.

수정: KADDRESS_KSIC_CODE_TO_LABEL 표를 신설해 코드(A~U) → 정식 select 값 변환을 반드시 거치도록 고쳤고, 레코드 생성 실패마다 console.error로 이메일+ PocketBase 에러 메시지를 남기고 응답에도 failedCount/failedSample(최대 20건)을 실어 프론트엔드가 바로 보여줄 수 있게 했다.

③ 실사 발견 버그
등록 경로 3곳 중 수동 등록 폼엔 중복 검사가 아예 없었다

연락처를 저장하는 경로는 세 곳이다: 수동 등록 폼 (/kmail/contacts/propose), CSV 업로드 (/kmail/contacts/csv-import), K-Address 대화 저장(_kmailChatSaveContacts). CSV 업로드와 대화 저장 두 곳엔 이미 이메일 중복 검사가 있었는데, propose 경로엔 처음부터 중복 검사가 없었다 — "새 연락처 등록" 폼으로 이미 있는 이메일을 다시 등록할 때마다 중복이 계속 쌓일 수 있는 구조였다.

추가로 세 곳 모두 이메일을 대소문자 그대로 비교하고 있어서 A@X.com과 a@x.com처럼 대소문자만 다른 주소는 중복으로 못 잡는 문제도 있었다.

수정: _kmailNormalizeEmail(소문자 정규화)· _kmailFindExistingContact(중복 조회) 공용 헬퍼를 신설해 세 경로 전부 저장 직전 이 헬퍼로 확인하도록 통일했다. 저장되는 이메일 자체도 항상 정규화한 값으로 남긴다.

④ 프론트엔드 신설
"메일" 탭 — 전형적인 메일 클라이언트 메뉴 구성

mail.hondi.net에 편지쓰기·임시보관함·보낸메일함·받은메일함· 태그별 보관함 다섯 서브탭을 갖춘 "메일" 탭을 신설했다. 백엔드는 대부분 이미 있던 것(mailbox/drafts/message-state)을 재사용하되, 아래 표의 다섯 엔드포인트가 전부 지갑 서명 인증만 지원하고 있었다는 걸 실사로 발견했다 — 지갑 SSO를 안 쓰는 이 웹앱에서는 호출 자체가 막혀 있었던 것이다. 공용 인증 게이트(_kAuth.resolveGuid)로 전부 이관해 phone_verify_token을 받아들이게 했다(지갑 서명 하위호환은 유지).

엔드포인트용도이관 전
GET /kmail/mailbox보낸메일함/받은메일함 목록지갑 서명만
GET/POST /kmail/drafts임시보관함 조회·저장지갑 서명만
POST /kmail/drafts/delete임시보관함 삭제지갑 서명만
GET/POST /kmail/messages/state라벨(태그)·별표·읽음 상태POST만 있었고 GET 자체가 없었음(신설)

태그별 보관함은 GET /kmail/messages/state로 이 owner의 라벨 상태 전체를 한 번에 가져와, 라벨별 건수 칩으로 요약해 보여주고 클릭하면 그 라벨이 붙은 메일만 모아 보여준다. 받은메일함에서 라벨을 직접 추가할 수 있다.

⑤ 편지쓰기 편집기
Quill(오픈소스 리치 텍스트 에디터) + Pretendard 폰트 강제

편지쓰기 본문을 일반 <textarea>에서 Quill 2.0.3(BSD-3-Clause, 4만+ GitHub star)로 교체했다 — 공식 CDN(jsdelivr) 사용, 굵게·기울임·밑줄·목록·링크 툴바.

Quill 기본 테마(snow)는 자체 폰트를 강제로 깔고 들어와서, .ql-toolbar/.ql-container/ .ql-editor/.ql-picker 전부 !important로 Pretendard(사이트가 이미 쓰던 --font 변수)를 덮어써야 실제로 적용됐다.

의도적으로 보수적으로 남겨둔 부분
서식(굵게·목록 등)은 편집 중 가독성 용도로만 쓰고, 임시저장· 발송 시엔 Quill.getText()로 일반 텍스트 변환해 보낸다. 실제 이메일 발송 파이프라인(env.EMAIL.send)이 HTML 본문을 지원하는지 코드만으로는 확인할 방법이 없어서, 그 경로를 건드려 발송 자체가 깨질 위험을 피했다.
⑥ K-Mail 대화 → 편집기 반영
이미 있던 KMAIL_SAVE_DRAFT를 "메일" 탭과 연결

K-Mail 채팅("새 캠페인" 탭)에는 이미 KMAIL_SAVE_DRAFT 초안 저장 태그가 있었고, 이게 "메일" 탭의 임시보관함과 같은 kmail_drafts 컬렉션을 쓴다는 걸 확인했다. 다만 지금까지는 draft_id만 돌려주고 정작 방금 쓴 제목·본문 자체를 안 줘서 화면에 바로 못 띄우고 있었다 — draft_saved/campaign_draft_updated 두 액션 응답에 subject/body를 실어 보내도록 고쳤다.

프론트엔드는 사용자가 명시적으로 "초안으로 저장해줘"라고 요청한 경우(draft_saved)만 편지쓰기 화면으로 직접 전환한다. K-Mail이 대화 도중 스스로 자주 체크포인트 하는 배경 동작(campaign_draft_updated)은 화면 전환 없이 내용만 조용히 채워둔다 — 매번 화면을 뺏으면 대화에 방해가 되기 때문이다. 이미 확정·예약된 캠페인 (campaign_created/campaign_started)은 의도적으로 제외했다 — 편집기에 다시 채우면 실수로 "보내기"를 눌러 중복 발송할 위험이 있다.

⑦ 실사 발견 버그
총 건수 질문에 200건 캡 샘플 크기를 답하던 문제

"주소록에 등록된 주소 숫자는?"이라고 물으면 실제로는 769건인데 K-Address가 "총 200건"이라고 답했다. 원인: 조회 기능 (_kmailQueryContacts)이 최대 200건까지만 가져오도록 캡이 걸려 있는데, AI가 이 샘플 크기를 그대로 총 건수인 것처럼 대답해버린 것이었다.

/kmail/contacts/category-counts에서 썼던 것과 같은 방식(perPage=1로 실제 레코드는 안 가져오고 totalItems만 읽음)으로 정확한 총 건수를 구하는 _kmailCountContacts를 신설해, K-Address·K-Mail 조회 기능 둘 다 "샘플 200건"과 "정확한 총 건수"를 분리해 AI에게 넘기도록 고쳤다.

다만 AI가 문장 속에서 숫자를 말로 옮기는 방식은 정확한 값을 넘겨줘도 다시 틀릴 여지가 남는다 — 그래서 조회 결과 배지 자체에 서버가 준 정확한 건수를 AI 문장을 거치지 않고 직접 붙였다("🔍 조회 결과 (769건)").

⑧ 검증
라이브 스모크테스트 — 20개 시나리오, 20/20 PASS

tests/live_smoketest/kaddress_contacts_live_smoketest.py 신설 — klaw_usage_billing_live_smoketest.py와 동일한 원칙으로, phone_verify_token을 오프라인으로 재현해 실제 worker.js 엔드포인트를 HTTP로 호출하고 PocketBase Admin API로 실제 저장 결과를 검증한다. LLM 호출이 없어 비용은 0원이다.

  • 카테고리 자동분류 10건(대학/병원/시청/감사위원회/연구소/협회/은행/방송/대사관 + 무매칭 빈 값 유지)
  • 이메일 도메인 폴백 2건(.ac.kr→P, .go.kr→O)
  • 중복 방지 4건(배치 내/배치 간/대소문자 무시/propose 회귀 가드)
  • category-counts 델타 정확도 1건
  • phone_verify_token 인증 3건(mailbox/drafts/message-state)

실계정(주소록을 실제로 갖고 있는 테스트 계정)을 쓰므로 모든 테스트 연락처는 pending_review로만 생성하고 종료 시 자동으로 rejected 처리해 정리한다. 첫 실행은 --test-e164에 형식이 안 맞는 번호를 넣어 20/20 FAIL이 났으나 (뒷자리 8자리만 입력 → PocketBase profiles와 안 맞음), 입력을 어떤 형식으로 넣어도 자동 정규화하도록 스크립트를 고친 뒤 재실행해 20/20 PASS를 확인했다.

Lessons
교훈
  • select 필드는 값 자체를 검증하라 — HTTP 200(ok:true)은 "의도한 대로 저장됐다"와 무관하다. 개별 레코드 생성 실패를 조용히 넘기지 말고 반드시 로그·응답에 남겨야 다음 사고를 빨리 잡는다.
  • "경로가 여러 개면 전부 같은 규칙을 지키는지 확인하라" — 같은 컬렉션에 쓰는 경로가 세 곳이면, 그중 하나가 다른 두 곳의 방어 로직을 안 갖고 있을 수 있다. 공용 헬퍼로 통일하면 이런 드리프트를 원천 차단한다.
  • 인증 방식 이관은 "쓰는 쪽"이 생기기 전까진 안 드러난다 — mailbox/drafts/message-state는 오래전부터 있었지만 지갑 서명만 지원한 채 아무도 몰랐다. 새 프론트엔드를 붙이려는 순간에야 발견됐다.
  • "샘플"과 "총계"는 반드시 분리해서 전달하라 — 캡이 걸린 목록 조회 결과를 총 건수 질문에 그대로 재사용하면, LLM이든 사람이든 착각하기 쉽다. count-only 쿼리를 따로 두는 게 싸고 정확하다.
  • 테스트 하네스의 입력 검증도 실사로 걸린다 — 스모크테스트 자체가 "전화번호 형식"이라는 흔한 실수로 20/20 실패한 뒤에야 정규화·사전 점검을 넣었다. 하네스도 사용자 입력을 받는 도구라는 걸 잊지 말 것.
