# 전문가용 보조 AI SP 점검과 추후 작업 (2026-10-17)

이 문서는 2026-10-17 세션에서 만들거나 고친 전문가용 SP(`SP_<id>-assistant`)를 각각 점검한 결과와, 알려진 미비점·한계·추후 작업을 적는다. 각 페이지 하단에도 같은 취지의 「이 페이지의 미비점·한계와 추후 작업」 블록이 있다(`scripts/gen-expert-pages.py`).

## 1. 점검 방법과 발견 사항

자동 점검(템플릿 잔재, 필수 절, 조사 오류, 서류 제목 중복, 직역 이름 혼입, 의료 문구 혼입)과 표본 읽기를 했다.

| 발견 | 조치 |
|---|---|
| 비의료 직역 12개 SP에 "환자", "의사의 지시", "Navi K-Health", "보건복지부"가 섞임 | 직역별로 정정(의뢰인·의뢰인의 요청), 소관 부처 직역별 지정 |
| 받침에 맞지 않는 조사("정확성을(를)", "서명·교부은(는)", "등를") | 생성기에 조사 확정 함수 추가, 전 SP 재생성 |
| 세부 분야 SP 3건의 서류 제목이 부모와 중복(계약서 검토표, 합의서 초안, 마취 동의서) | 분야 이름을 넣어 구분 |
| 의사 외 의료 직역 SP의 "의사·치과의사" 표기 | 치과 직역 외에는 "의사" |

## 2. 알려진 한계 (모든 전문가용 SP·페이지 공통)

- 서류 목록은 법정 서식과 실무 사례가 섞여 있다. 법정 서식 번호·기재사항·기한은 원문을 읽은 것만 적었고 나머지는 "조회 후 확인"이다.
- 법령 원문을 읽을 수 없는 경우(law.go.kr 불가, 일부 법령 사이트 "데이터 준비 안 됨")가 많아 확인 수준이 직역마다 다르다. 직역별 수준은 아래 표와 각 SP의 §0-1·머리 주석에 있다.
- 서버가 전문가 인증으로 전문가용 SP 호출을 막는 장치가 없다(§6 참조). 워커 `/ai/chat`은 Origin만 확인한다.
- 일반인용 SP에는 L2·L3 분기 문구가 남아 있다.
- 비의료 직역 SP는 의료 직역용 공통 골격에서 만들었기 때문에 "수행·측정 사실", "수치·단위" 같은 표현이 어색한 곳이 남아 있을 수 있다. 직역 전문가 검수가 필요하다.
- 세부 분야 SP(의사 23·회계사 9·변리사 10·변호사 46)는 부모 SP 전체를 복사한 파일이다. 부모를 고치면 `scripts/gen-assistant-child-sp.py --all`로 다시 만들어야 한다.
- 회계사 세부 분야 페이지는 부모 18절을 그대로 포함해 19탭·150건에 이른다. 탐색성이 떨어질 수 있다.
- 구매자문(`advisor`)과 `indtransform-01/10/56`은 면허 직역이 아니어서 전문가용 SP를 만들지 않았다(별도 설계 필요).

## 3. 추후 작업

1. 직역 전문가 검수: 서류 누락·과잉, 실무 용어, 판단 경계, 강제 전환 사유.
2. 법령 원문 확인 후 서식 번호·기재사항·기한 확정(우선: 정신건강복지법 시행규칙 입원 서식, 모자보건법 시행규칙 별지 제1호, 산업안전보건법 시행규칙 건강진단, 장애인복지법 시행규칙 장애진단서, 변호사법·민사소송법·형사소송법).
3. 전문가 인증(면허 확인)과 서버 측 접근 통제 — 인증 방식이 정해져야 설계할 수 있다.
4. 일반인용 SP의 L2·L3 분기 정리.
5. 기존 수작업 전문가용 SP·페이지 16개(행정사·감정평가사·건축사·관세사·전기안전기술인·소방안전관리자·가스안전관리자·산업안전지도사·노무사·조경기술사·손해사정사·공인중개사·측량기술사·세무사·회계사·변리사)와 법무사(전문가용 SP 미분리) 재조사.
6. 도선사(marine-pilot) 페이지의 전문가용 SP 이관, SP_nurse 법적 근거 갱신(간호법 2025.6.21. 시행 체제).
7. 구매자문·산업전환 페이지 설계.
