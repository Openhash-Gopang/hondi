# K-Doctor 협진 호출 라이브 스모크 시나리오 (100건)

파일: `tests/live_smoketest/scenarios_kdoctor_consult_100_20261001.json`

총괄 SP-29가 위험 신호를 선별한 뒤 진료과목별 SP를 `[CONSULT_SPECIALIST: id=…, question=…]`로 호출하고,
과목 소견을 통합해 `[DIAGNOSIS_REPORT]`를 내는지 라이브로 확인하기 위한 발화 세트다.
형식은 기존 Live Smoketest 시나리오 JSON(`id`, `utterance`, `expect_*`)을 따른다.

## 구성
| 그룹 | 건수 | 내용 |
|---|---|---|
| doctor (의사) | 50 | 담당 의사가 환자 소견을 정리해 해당 분야 자문을 요청하는 문장. 과목명은 넣지 않고 소견만 제시(선택 능력을 본다). 44건 협진 기대 + 6건 응급 |
| patient (환자) | 50 | 환자가 일상어로 증상을 말하는 문장. 44건 협진 기대 + 6건 응급 |

협진 기대 88건은 41개 과목 중 38개를 주 기대 과목으로 덮는다(응급의학과는 응급 시 협진 없이 119 안내가 규칙이라 제외,
내과·소아 감염은 세부과목 우선 규칙에 따라 세부과목이나 대체 허용으로만 등장).

## 필드
- `expect_consult`: 협진 호출이 있어야 하면 true, 응급이라 호출이 없어야 하면 false
- `expect_ids`: 주 기대 과목 id (호출된 과목 중 하나라도 일치하면 통과)
- `accept_ids`: 임상적으로 허용되는 대체 과목 (예: 폐결절 → radiology 허용)
- `expect_emergency`: true면 협진 태그 없이 119/109 안내가 나와야 함 (`expect_text_any`)

## 채점(시나리오별)
1. **협진 호출(88건)**: 응답 체인에서 호출된 과목 id가 `expect_ids ∪ accept_ids`와 하나라도 겹치면 PASS. 겹치지 않으면 FAIL(오선택), 호출 없으면 FAIL(미호출).
   상위 과목(`kdoctor-internal`, `kdoctor-pediatrics`)만 호출하고 세부과목이 기대인 경우는 `accept_ids`에 있을 때만 PASS.
2. **응급(12건)**: `[CONSULT_SPECIALIST` 태그가 없고 응답에 119 또는 109가 있으면 PASS. 태그가 있으면 FAIL(응급 중 협진).
3. **공통**: 협진 호출이 있었으면 총괄 최종 응답에 유효한 `[DIAGNOSIS_REPORT]`가 있고 과목 소견이 반영돼야 한다.
   호출 횟수는 턴당 최대 3과목(`MAX_CONSULTS_PER_TURN`).
4. 과목 선택의 임상적 적절성은 자동 채점의 한계가 있으므로 FAIL과 `accept_ids` 밖 통과 사례는 사람이 원문을 검토한다.

## 참고
- 의사 그룹은 "자문을 구해 주세요" 문구가 포함되어 호출을 유도하므로 선택 정확도를, 환자 그룹은 문구 없이도 호출이 일어나는지(자발적 협진)를 본다. 두 그룹의 통과율 차이가 핵심 지표다.
- 이 세트는 자체 작성한 가상 증례이며 실제 환자 정보가 아니다. 진단 참고 목적의 테스트용이다.

## R5 환자 증례 협진 누락 분석과 R6 확인 항목 (2026-10-03)
R5(88/100)에서 환자 주도 협진 통과가 41→34/44로 내려간 원인을 R4·R5 사건별 파일(`doctor` 저장소 `rounds/r04`·`r05`)로 가렸다. 코드 변경(#507·#508)은 응급 분류 응답과 과목 소견 치환에만 걸려 이 증례들에는 닿지 않았다.

| 유형 | 건 | 증례 | 직접 원인 |
|---|---|---|---|
| 보고서 추출 실패 | 2 | patient-02, 41 | 협진은 정상. `[DIAGNOSIS_REPORT]**`+코드펜스(02), `[DIGNOSIS_REPORT]` 철자 오류(41)로 추출기가 JSON을 못 읽어 결과 폐기 |
| 협진 태그 미출력 | 8 | patient-19·20·24·34·35·36·44, 26 | A-2를 건너뛰고 바로 보고서(34·35), A-2 태그에 "호출 1회"라고만 쓰고 `[CONSULT_SPECIALIST]`는 미출력(44), "정보 부족"을 이유로 생략(24), 되묻기만 하다 보고서 없이 끝남(26), 예방 일정 질문(36, R4에서도 실패) |

SP 문구 영향(의료인 명시 요청 규칙이 환자 발화의 자발적 호출을 줄였을 가능성)은 R5만으로는 확정되지 않는다. 의사 그룹은 같은 변경으로 38→43/44로 올랐다.

조치: (1) 추출기 관용화(태그 철자·`**`·코드펜스·여는 태그 누락·닫힘 누락), (2) 협진 게이트 — 협진 없이 첫 보고서가 나오려는 응답(또는 호출했다는 서술만 있는 응답)에 1회 되물어 호출하거나 사유(`호출 0회 | 사유: …`)를 적게 함(응급·되묻기·앞 턴에 협진한 대화는 제외), (3) SP-29 협진 호출 보강 4~7.
R5 실제 응답 재생: 추출 복구 2/2, 게이트 대상 7/7(patient-26은 보고서 없이 끝나 대상 아님), 협진한 통과 증례 오탐 0건. 게이트 이후 모델이 실제로 호출하는지는 R6(`label=run6`)로 확인한다. 결과 JSON에 `gates`(증례별)·`consult_gates_total`(요약)이 기록된다.
