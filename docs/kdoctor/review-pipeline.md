# K-Doctor 진단·처치/처방 표준 흐름 — 생성 → 독립 검수 → 재조정 (2026-10-02)

K-Law 방법론(v17.1)과 검수 SP(K-Law-Check v1.2)의 논리를 진료에 옮긴 것이다. 핵심은 "생성자가 자기 결과를 믿지 못하게 하는
장치"를 겹겹이 두는 것이다.

## 역할

| 역할 | 구현 | 비고 |
|---|---|---|
| 총괄 의사 AI | `prompts/SP-29_kdoctor_v0_1.txt` | 접수·위험 신호 선별(STEP T)·협진 호출·최종 취합·재조정 |
| 전문 과목 의사 AI | 과목 SP 41개 | 좁은 질문 하나에 소견 |
| 진단·처치/처방 AI | 현재는 총괄의 STEP A·STEP B 단계 | 테스트는 같은 AI, 상용은 별도 AI로 분리(결정 2026-10-02) |
| 검수 AI | `prompts/SP-29K_kdoctor_check_v0_1.txt` | 별도 호출·별도 키(`DEEPSEEK_CHECK_KEY`). 테스트는 같은 모델, 상용은 다른 모델 |

## 흐름

1. 위험 신호 선별: emergency면 환자 발화에서는 협진을 부르지 않는다. 의료인이 자문을 명시 요청하면 요청 과목을 호출한다(`explicitConsultRequest`).
2. 협진 → 총괄이 `[DIAGNOSIS_REPORT]` 작성 → 코드 검증기(`hondi-doctor-verdict.js`)가 확신도·응급·금지 표현을 다시 계산.
3. **독립 검수(항상)**: 검수 AI는 사례 원문·협진 소견 원문·보고서만 본다. 정답이나 총괄의 사고 과정은 받지 않는다.
   열린 재판단 대신 문자열 대조와 구체 명칭 열거만 한다(C-1 인용 대조, C-2 구조적 열거, C-3 프레임 대체, C-4 대상 대조, C-5 이득·위해, C-6 결정 규범 의존).
   출력은 `[FINDING | C-n | HIGH/MED/LOW | 결론영향:있음/없음/불명 | …]`와 `[CHECK_VERDICT: 재검토 불요/권고/결론 무효 소지]`.
4. **재조정**: 판정이 '불요'가 아니면 총괄이 지적마다 `[수용]/[반박]` + 근거 인용 + 결론 영향을 쓰고, 완결된 `[DIAGNOSIS_REPORT]`를 다시 낸다.
   결론 영향이 불명이면 결론을 낮춘다. 재조정 결과도 같은 검증기를 통과해야 채택되며, **응급 보고서는 재조정으로 낮출 수 없다**.
   실패하면 원 보고서를 유지하고 상태만 남긴다. 검수 호출이 실패해도 원 보고서를 낸다.
5. 최종 보고서만 대화 이력에 남긴다(수용·반박 문장은 남기지 않는다). 위젯 상태줄에 검수 판정이 표시된다.

## 평가

- 오류 주입 파일럿: `tests/live_smoketest/kdoctor_check_pilot.mjs` (결함 10건·정상 대조 3건). 워크플로 `live-smoketest-kdoctor-check-pilot`.
  K-Law-Check가 616497·617151로 먼저 검증된 것과 같은 방식이다. 전면 적용 전에 기대 모듈 검출률과 오경보를 확인한다.
- 협진 라이브 스모크 100건은 기본으로 검수를 켠다(`--review on|off`). 결과 요약에 판정 분포·재조정 반영 수·모듈별 지적 수가 나온다.
- 평가 원칙(K-Law에서 차용): 사례 특화 규칙을 만들지 않는다. 변경마다 근거·일반성·부작용·검증 지표를 기록한다.
  1라운드 사례(협진 100건 87/100)로는 일반화를 증명하지 않고 새 사례로 증명한다. 평가·중단 기준은 사전에 정한다.

## 한계

- 지금은 1차 생성과 같은 모델(다른 키)이 검수한다. 같은 모델은 맹점을 공유하므로(에코 챔버) 독립성이 제한적이다. 상용은 다른 모델로 바꾼다.
- 검수 SP와 보고서의 임상 내용은 전문의 검토를 거치지 않았다.
- 응답 시간이 늘어난다(검수 1회, 지적이 있으면 재조정 1~2회). 워커 분당 한도를 60회로 올렸다.
