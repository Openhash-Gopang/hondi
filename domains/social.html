사교의 원칙

모임은 연결하되, 관계는 만들지 않습니다

"AI가 성향을 분석해서 나에게 딱 맞는 사람을 찾아준다" — 사교 영역에서 가장 먼저 떠오르는 상상이지만, 나비는 이 방식을 택하지 않았습니다. 위치·관심사·일정을 교차분석해 사람을 짝지어주는 매칭 알고리즘은 실제로 만들지 않았고, 대신 관심사 기반 모임을 실제로 만들고, 검색하고, 참여 의사를 표시하는 것까지만 지원합니다. 그 모임 안에서 실제로 이야기를 나누는 건 기존 나비 P2P 메시징으로 넘어갑니다 — 나비가 대화 내용을 대신 만들거나 관계를 주선하지 않습니다.

대화 예시

추천은 하되, 선은 지킵니다

이용자 "이번 주말에 사람들이랑 좀 어울리고 싶은데, 나한테 맞을 만한 모임 있는지 알아봐 줄래?"

나비 피터님 성향에 맞을 만한 모임이 두 곳 보이네요. 제주 올레길·오름을 함께 걷는 "나올레"랑, 가볍게 노래와 춤을 곁들이는 "바라던 바다" — 이번 주말 일정으로 참가 신청서를 넣어드릴까요?

주피터 "뚜껑열리는 나이트 어때?"

나비 심정은 이해가지만, 권하지는 않습니다. 작년에도 와이프에게 걸려서...

주피터 "아, 됐고."

"성향에 맞는 모임을 골라 보여주는" 부분은 실제로는 카테고리 태그로 걸러 보여주는 수준입니다 — 나비가 사람의 성격을 분석해 점수를 매기는 게 아니라, 이미 열려있는 모임 목록을 사용자가 관심 있어할 만한 태그로 정렬해 보여주는 것에 가깝습니다.

체험해보기 · PDV 기반 추천

성향·취미를 실제 모임과 대조합니다

DeepSeek API 실시간 호출 성향·취미를 입력하면, 지금 실제로 열려있는 모임 목록(위 섹션과 같은 실 데이터)을 AI가 대조해 관련성 높은 후보를 추천합니다. 실제 PDV 자동 조회는 아직 연결되지 않아, 입력한 텍스트가 PDV 요약을 대신합니다 — 모임 데이터는 진짜, 성향 조회는 시뮬레이션입니다.

성향·취미를 입력하세요

실제 흐름

만들고, 찾고, 참여 의사를 표시합니다

  1. 모임 만들기
    제목·카테고리·설명을 정해 새 모임을 엽니다. 만든 사람이 자동으로 첫 참여자(1명)가 됩니다.
  2. 검색·필터
    열려있는(status=open) 모임을 카테고리로 걸러 봅니다 — 서버는 원본 데이터를 그대로 줄 뿐, 알고리즘이 사용자별로 순위를 매기지 않습니다.
  3. 참여 의사 표시
    "참여하고 싶다"를 누르면 참여자 수가 1명 늘어납니다. 이 단계는 의사 표시일 뿐, 실제 확정된 회원 가입이 아닙니다.
  4. 실제 대화는 P2P로
    참여 의사를 표시한 이후의 실제 대화·약속 조율은 나비의 기존 사람 대 사람 메시징으로 이어집니다. 이 흐름을 위한 별도의 새 채팅 시스템은 만들지 않았습니다.
정직한 한계

"추천"이라는 말이 가리키는 범위

알고리즘 매칭은 없습니다. 위치·관심사·일정 교차분석으로 "이 사람과 잘 맞을 것"을 계산하는 기능은 만들지 않았습니다. 지금 할 수 있는 건 모임을 만들고, 검색하고, 참여 의사를 표시하는 것까지입니다. "추천"이라는 표현은 카테고리 태그로 목록을 걸러 보여주는 수준을 뜻합니다.
